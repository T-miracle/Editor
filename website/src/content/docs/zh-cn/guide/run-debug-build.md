# 运行、调试与构建

顶栏在插件管理旁显示一个配置下拉和构建、运行、调试、停止四个图标按钮。下拉框位于按钮正下方：分割线上方是已保存的配置列表，下方的**编辑配置**打开配置窗口；列表为空时显示浅灰色的**暂无配置**。选择配置不会启动程序。悬浮图标可查看操作或禁用原因。普通执行处于停止中时，停止按钮位置提供立即终止。

## 选择配置

打开**编辑配置**新建或编辑配置。配置与插件管理一样，使用位于父窗口上方的独立原生弹窗。再次打开会激活同一窗口。打开时跟随外部已选择的配置；没有选择时，右栏显示**请添加配置**。

加号打开覆盖左侧列表的抽屉。已启用的兼容插件提供分组命令模板、图标、名称和默认值。选择模板后创建独立的未保存配置，并显示插件自己的原生表单。程序只读，完整参数可以编辑，包括插件预填的子命令；空格、引号和标点保留原参数边界。其他字段和业务校验同样由插件提供。

**应用**校验并保存当前配置，保留窗口和其他草稿。**保存**等待编辑完成，校验全部配置，保存草稿并关闭窗口。校验失败或不可用的配置仍可编辑，不能运行；磁盘写入失败时保留窗口。**取消**丢弃未应用的修改，保留此前应用成功的数据。编辑与保存都不启动程序。

配置按工作区保存在本机，不创建项目配置文件，也不授予插件权限。提供者消失时显示不可用原因；执行不会静默切换提供者或沿用旧校验结果。

## 构建与启动

Nanobug 分组始终提供“插件打包”“插件调试”，选择后创建配置草稿。插件打包每行填写一个项目目录，ZIP 输出目录可手动输入或通过选择器设置。留空使用各项目的共享默认位置，通常是各自项目根目录。“运行”构建并为每个项目生成 ZIP；“构建”仅准备产物，不生成 ZIP。

插件调试填写一个项目和可选测试工作区。“运行”确认信任／权限后打开独立编辑器，隔离设置、插件、私有数据及历史。随附插件仍然可用，同 ID 使用开发版本。数据按配置保留；选择“重置开发环境”前需停止实例。输出面板提供“重新加载插件”，也可选自动重载；重载失败保留旧版。“构建”仅准备产物，不打开窗口；暂不支持 WASM 源码断点，“调试”禁用。项目声明见[打包与开发运行](/zh-cn/sdk/packaging/)。

Rust 插件提供 **Cargo** 分组的 run、build、debug 模板，默认参数分别为 `run --release`、
`build --release`、`run`，这些参数都可以修改。缺少 Cargo 或根目录 Cargo 项目时，普通
模板置灰并说明原因。调试使用真实 Cargo 产物，支持 dev/debug 和 release 构建配置；
存在多个适用程序时要求通过 `--package`／`--bin` 明确选择。

内置终端仅显示当前操作系统中已安装的 Shell 模板。解释器只读，参数和多行脚本可编辑；
工作目录与环境变量放在“更多设置”中。Shell 模板不支持调试。原终端插件创建的配置会
保留参数与执行引用并迁移，无需终端包。

从底栏第二个图标打开终端。空面板自动添加 Shell Tab，关闭最后一个 Tab 后隐藏面板。
双击 Tab 可改名，Enter 或失焦保存；拖动可排序。终端设置控制侧栏位置和宽度、字体、
历史容量及主题色。Ctrl+C 复制选中文本，Ctrl+V 粘贴，Ctrl+Shift+T 新增 Shell，
Ctrl+Shift+W 关闭当前 Tab，Shift+PageUp/PageDown 滚动历史。右键菜单提供复制（仅有选区
时可用）、粘贴和清空缓冲区；有可滚动历史时才显示滚动条，停止滚动一秒后隐藏。

从旧终端插件升级时，先备份设置、名称、顺序、目录、输出和布局再导入。受信任工作区
在保存的逻辑画面上重建新 Shell；旧任务保持停止，不自动重跑命令。导入失败会保留原
数据、显示错误并阻止自动写入；修复错误中指出的数据源后，重新打开编辑器重试。原有
MeEditor 用户数据目录保持使用。

左栏工具区提供添加、删除、复制、添加文件夹四个图标按钮，悬浮可查看名称。文件夹只是虚拟分组。新增项放入选中文件夹、选中配置的同级，或无选择时的根目录；点击树的空白处取消选择。F2 或双击可重命名文件夹；点击箭头展开或收起。

拖入文件夹或树的空白处可移动到对应父级或根目录；行前间隙用于调整同类别顺序，文件夹始终在配置前。移入后代会被拒绝。复制创建同级独立副本。删除先显示递归影响的文件夹与配置数量，只改草稿；保存提交删除，取消保留此前应用的数据。存在未应用修改时，X 或 Esc 提供保存、放弃修改、继续编辑三条路径。

构建按顺序执行构建步骤，不启动最终程序。运行先通过普通保存路径保存修改文档，再执行构建及运行前步骤，最终启动一次；磁盘冲突或保存失败阻止启动。准备失败显示失败步骤和输出，不启动程序。

提供者可为选中目标和配置产出确切构建产物，例如 debug 与 release 配置保持独立，构建不替换成无关可执行文件。本轮采用有效配置快照，后续修改不改变正在运行的一轮。

不同配置可并行运行；选择会话只改变控件作用对象。隐藏输出保留程序，定位恢复同一会话。停止请求正常清理，有界宽限后升级；强制停止立即作用于选中会话的所属进程树，停止中状态保留至观察到真实原生结束。重新运行先等待上一轮清理完成，再开始准备。

## 调试检查

调试要求兼容且已启用的提供者、可用配置与适当工作区权限。Shell、构建、运行和调试 Tab 共用底部终端面板。选中调试 Tab 后，在其命令行区域下方显示控制、已绑定／未绑定断点、源位置、调用栈和局部变量；提供者不支持的控件带原因禁用。支持终端展示的提供者可将唯一调试目标接入独立 PTY：在命令行区域输入会发送给目标，与调试协议消息隔离。

真实暂停打开提供者报告的源位置；选择另一帧后读取该帧局部变量。继续与单步使旧暂停检查失效，迟到结果不能覆盖新暂停或其他会话。调试面板获得焦点时，F5 继续、Shift+F5 停止、F6 暂停、F10 跨过、F11 进入、Shift+F11 跳出，Up/Down 选择帧。

隐藏面板保留调试。停止回收目标与适配器，强制停止只作用于该会话。停用、卸载、更新受影响插件或离开工作区／窗口前，编辑器列出受影响工作；取消保留插件和会话，确认退役会清理，不自动重跑用户命令。

插件作者可通过公开 SDK 实现[运行会话](/zh-cn/sdk/sessions/)、[调试会话](/zh-cn/sdk/debug/)及[目标发现与准备](/zh-cn/sdk/targets/)。
