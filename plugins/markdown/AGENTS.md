# Markdown 插件 AI 执行约定

本文件补充仓库根部 AGENTS.md。用户当前明确要求优先；其余继承仓库原生 UI、插件平台、代码注释、验证与 Git 约束。

## 资料位置与阅读顺序

用户明确要求本插件总方案、工单放在插件目录内；这仅覆盖仓库中央归档的默认位置，不改变架构、权限或验证规则。中央索引保留链接，不再维护另一份总方案正文。

1. 检查工作区提供的仓库根 AGENTS.md（存在时阅读）和用户当前协作约定，再读[需求基线](../../docs/project/需求整理.md)、[开发计划](../../docs/project/开发计划.md)，检查 git status --short，辨别用户和其他任务的已有改动。不得依赖其他聊天尚未提交的文档副本。
2. 阅读[总方案](docs/spec.md)和[工单目录](docs/tickets/README.md)，然后读本次工单及其直接前置工单和实际验收记录。
3. 阅读[插件平台规格](../../docs/plugins/specs/plugin-api-platform.md)、[领域约定](../../docs/agents/domain.md)、[议题约定](../../docs/agents/issue-tracker.md)及涉及的[公开协议](../../crates/plugin-protocol/README.md)专题；修改宿主目录前检查该目录约定。资料重归档后，以实际跟踪的文件为准更新这些链接。
4. 核对已安装公共能力、相关实现、调用方与测试；不要把当前 API 缺失或历史实现当作缩减需求的理由。

## 任务状态与执行

- 用户已明确要求连续执行所有 11 张工单，产品需求、拆分及验证主线已获批准。状态以工单、验收记录与 tracker 读回为准；授权不等于功能已实现。
- 只执行用户要求且所有阻塞项已完成的一张前沿工单；编号与 tracker issue 编号分别处理，不依赖缓存进度。
- 每张工单先处理必要预重构：保持现有行为并验证，再实现新行为。不在无证据时扩大为广域重构；不交付只有协议、只有 UI 外壳或未接真实包的水平阶段。
- 工单开始时写清目标、前置证据与本单边界，完成时同步工单、目录与验证记录，使新上下文能独立接续。不需要为清空上下文而擅自创建新聊天。
- 依赖可并行不等于授权多代理；遵守仓库与会话已有的委派条件。

## 本插件必须保持的行为

- Markdown 默认左源码右预览，三种模式与同步开关按工作区记忆。格式工具栏位于源码区顶部，模式按钮在底栏左侧现有工具组右边，以短竖线分隔；同步开关在模式组右边。
- 格式工具栏使用统一 24 × 24 设计网格、2 px 描边的 SVG 图标，保留中英文提示；十八个按钮包含 H1～H6，默认无底色，原生按钮 24 px 高，窄宽度换行。标题在光标行或选中行替换现有级别，同级取消，不新建行；空白行保留可编辑占位模板。
- 预览使用通用 github role 的 GitHub Primer 深浅配色，行内代码必须显式使用正文前景色。底栏 Toolbar 图标与三个模式按钮、同步开关同属一组，紧随同步滚动且间隔一致，title 为“隐藏/显示Markdown工具栏”（含英文），只控制顶部工具栏，不能关闭预览；显隐按工作区记忆，切换普通文件只隐藏整组预览控件、不改变或重置该偏好。
- 小幅预览滚动也必须应用真实源码位移；定位先应用精确提议，再允许布局舍入容差，不在应用前吞掉亚像素进度。
- 同一源码版本的启动配置或布局刷新必须保留最近手动滚动的一侧，撤销过期定位请求；不能让仍在顶部的另一侧重排通知覆盖用户已滚动的位置。同一文件的新 revision 同样不得放弃上次手动驱动的一侧；只有换文件才重新从顶部对齐。
- GFM 表格的每个单元格都是独立的原生富文本块（表头使用 muted 表面并按行绘制分隔线），不得把整张表合并成一个富文本节点：同一节点内的多个行内代码片段会共用原生内联状态，导致除最后一个单元格外全部丢失字形。
- 输入不得撤回用户正在阅读的预览：同一文件在途发布期间继续显示上一棵树，连续输入合并为一次在途发布，访客回答后补发最新文本；同时不得从渲染路径之外重复触发整体重建。
- 图片保存到 Markdown 同级目录，按 img、img1、img2 加实际格式后缀命名，不建 assets 子目录，不覆盖已有文件。
- 预览任务框可写回并撤销，其他内容只读。同步滚动按内容块双向定位，避免反馈循环与旧 revision 映射。
- 原生 GPUI；Markdown 领域逻辑归插件，所需缺失能力以公开通用契约扩展。禁止宿主按 Markdown 插件 ID、语言名称或扩展名执行专属业务。
- 源码及代码块高亮使用插件 WASM grammar 和已启用提供者；不得恢复宿主内建 grammar。
- EditorState 是唯一内存文本、选区、IME、布局和 Undo/Redo 真相来源。经 DocumentSession 提交编辑，严格检查文档身份与 revision，派生只读快照不成为第二份可变文档。
- 网络、文件、剪贴板及外部导航按公开权限和受控入口执行；受限工作区不启动插件，默认提供不覆盖用户禁用、卸载及提供者选择。
- 若生成代码，必须同时生成意图、接口、边界与生命周期所需注释；使用 apply_patch 编辑，保留无关改动。

## 验证与验收记录

- 主路径是实际包经公开 Manager 进入宿主集成，再以原生交互观察结果；复用 SVG 预览和组合 UI 先例，不增加本插件专用宿主测试入口。
- 每单完成相应验收标准后，执行针对性测试及根约定的 cargo fmt --check、cargo test --workspace --exclude editor-app、cargo check --workspace；涉及 editor-app 追加相关测试和必要原生交互。
- 真实 WASM 先按脚本参数构建；显式运行相应 ignored 测试。SDK 分发变更按根约定先构建宿主，再执行 SDK 验证；不擅自安装缺失工具。
- 在 docs/verification/ 中按工单保存实际命令、结果、包版本、环境、失败归因及未验证限制，并维护目录。纯文档变更只需链接、路径、状态、依赖和 git diff --check，不运行无关 Rust 全量构建。
- 原生验收包含本单相关的主题、键盘、中文 IME、焦点、滚动、缩放和资源撤销。编译成功、跳过测试和仅内部状态断言不等于行为验收。

## 发布与 Git

- 方案和工单发布需按已批准拆分操作，使用 ready-for-agent；原生阻塞关系与本地依赖一致，发布映射保存真实 ID 与 URL，不创建虚假占位编号。
- 不关闭或修改父方案来推进工单。发布工单不自动授权实现或 Git 提交。
- 用户后续明确要求执行工单时，按根约定与议题工作流既有授权完成实现、测试审查及相应交付；不擅自强推、改历史或发布版本。
