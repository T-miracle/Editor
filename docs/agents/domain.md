# 领域文档使用约定

本仓库按单个编辑器产品上下文阅读领域资料，不因 Rust workspace 中存在多个 crate 就拆出多个领域上下文。

- 开始工作前阅读仓库现有代理约定、需求基线与开发计划。
- 如果存在 CONTEXT.md、CONTEXT-MAP.md 或相关 ADR，按其组织读取；没有这些文件时不凭空声称已有术语表或决策记录。
- 插件平台重构使用已确认规格中的术语：宿主、插件包、贡献、能力接口、提供者、实例、WASM 钩子、服务契约、服务依赖、资源句柄、文档 revision 与状态快照。
- [插件平台 API 规格](../plugins/specs/plugin-api-platform.md)记录本次用户确认的新决策及其对旧规范的明确替代范围。
- [插件 UI 解耦与文件显示布局规格](../plugins/specs/plugin-ui-decoupling.md)补充文件 Tab、可选文本会话、文件显示提供者、中心布局及两组底栏按钮的定义；产品边界已确认，功能待实施。
- [实施工单目录](../plugins/tickets/README.md)记录依赖顺序与验收覆盖，不能把编号顺序等同于全部串行执行。
- 未被新决策替代的工作区信任、唯一文档状态、revision 检查、动态 WASM grammar 与原生 UI 基座约束继续有效。
- 发现规则冲突应指出涉及的条款；不得静默把历史规范或已确认新方案覆盖掉。
