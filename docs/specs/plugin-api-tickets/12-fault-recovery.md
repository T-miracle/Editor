# 12 — 定位插件超限与 LSP 崩溃并独立恢复

**Status:** ready-for-agent — 已发布，未开始实现；须等待全部阻塞项完成

**GitHub:** [#13](https://github.com/T-miracle/Editor/issues/13)

**Parent:** [设计基线 #1](https://github.com/T-miracle/Editor/issues/1)

## What to build

WASM 钩子超限或语言服务崩溃时，用户在插件状态中看到原因，有限重试后可手动重启，编辑器和其他插件继续可用。

增强前序已存在的基本执行约束，完成面向用户的故障诊断与恢复闭环；不延后基本安全限制到此工单才引入。

## Acceptance criteria

- [ ] 明确可测试的执行时间、内存和队列策略参数，超限中止本次执行，反复失败暂停实例。
- [ ] 原生服务有限次数重试并有等待策略，持续失败停止自动循环。
- [ ] 错误与日志关联插件、作用域和操作，提供独立重启，不能要求整个编辑器重启。
- [ ] 耗时任务不阻塞 UI；一个夹具失败期间另一个实例和文档编辑仍正常。
- [ ] 失败请求全部结束、失效资源回收，旧服务迟到事件不污染重启实例。
- [ ] 恢复失败如实报告，保留可恢复状态，不宣称原生进程隔离可约束所有系统资源。

死循环/超内存 WASM 与崩溃 LSP 夹具配合可控时钟，验证预算、重试上限、手动恢复及正常插件不受影响。

规格验收覆盖：T21、T22。

## Implementation guardrails

- 使用已确认的现有包管理器与编辑器集成测试边界，不新增插件专属测试入口。
- 只改变本工单范围，保留工作区已有改动；新增代码同时补充意图和不变量注释。
- 复用既有模块；必要的预重构先保持行为不变并通过相关回归，再加入新行为。
- 测试使用隔离目录与夹具，不操作用户真实插件安装数据；不提交 Git、不发布中间版本。
- 流程与契约细化若改变已确认产品行为，应先评审；不能以实现方便引入插件专属分支。
