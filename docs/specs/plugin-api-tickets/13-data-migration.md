# 13 — 通过隔离数据副本迁移插件私有状态

**Parent:** [设计基线 #1](https://github.com/T-miracle/Editor/issues/1)

## What to build

安装数据格式升级的插件版本时，用户设置通过插件钩子转换；迁移失败保留旧数据，准备期间旧版本写入不会丢失。

先通过仅持有私有数据与基础界面的插件完成迁移事务，后续工单将同一事务接入服务与多种贡献的切换。

## Acceptance criteria

- [ ] 插件声明数据格式版本及迁移钩子，宿主只理解版本与事务，不解释业务字段。
- [ ] 迁移在隔离副本运行，限制其操作范围；钩子不能写项目文件或修改正式数据。
- [ ] 准备期间旧版本继续使用；最终切换获得一致数据版本，过期迁移副本不能覆盖较新的写入。
- [ ] 迁移失败丢弃副本，激活及提交失败恢复原数据，首次安装失败也不留下可用状态假象。
- [ ] 明确持久化提交顺序和中断恢复记录；模拟恢复无法完成时保留数据并明确报错。
- [ ] 进程和连接不是快照内容，项目及外部系统不纳入自动回滚。

## Implementation guardrails

- 使用已确认的现有包管理器与编辑器集成测试边界，不新增插件专属测试入口。
- 只改变本工单范围，保留工作区已有改动；新增代码同时补充意图和不变量注释。
- 复用既有模块；必要的预重构先保持行为不变并通过相关回归，再加入新行为。
- 测试使用隔离目录与夹具，不操作用户真实插件安装数据；不提交 Git、不发布中间版本。
- 流程与契约细化若改变已确认产品行为，应先评审；不能以实现方便引入插件专属分支。
