## What to build

通过宿主公开构建入口构建一个独立示例包，安装后展示界面并完成一次类型化包资源读取。能力不满足时，在激活前获得明确说明。

这是新协议的第一条纵向路径，同时承担广域迁移的扩展阶段。演进既有协议、SDK、管理器和最小 UI 适配，不先建立只有类型定义而没有消费者的框架。

## Acceptance criteria

- [x] 定义基础协议、独立能力标识及版本区间，落实必需和可选能力协商；包版本与能力版本分离。
- [x] 独立示例包通过宿主公开 SDK 构建，使用最小原生文本界面和类型化包资源读取；不引用宿主业务源码。
- [x] 安装确认、权限检查、准备、激活、显示与卸载形成完整流程；保留已有的基本 WASM 执行限制。
- [x] 缺少必需能力明确拒绝，缺少可选能力按声明降级，未知操作和参数错误返回类型化失败。
- [x] 依照新契约承载请求关联和结果，不为示例插件添加宿主 ID 分支。
- [x] 开发中旧形式暂时存在时维持现有回归可运行；明确仅为迁移过渡，不发布双协议正式产品。

## Implementation guardrails

- 使用已确认的现有包管理器与编辑器集成测试边界，不新增插件专属测试入口。
- 只改变本工单范围，保留工作区已有改动；新增代码同时补充意图和不变量注释。
- 复用既有模块；必要的预重构先保持行为不变并通过相关回归，再加入新行为。
- 测试使用隔离目录与夹具，不操作用户真实插件安装数据；未经用户授权不提交 Git，不发布中间版本。本次普通提交与关闭工单已于 2026-10-02 获得用户明确授权。
- 流程与契约细化若改变已确认产品行为，应先评审；不能以实现方便引入插件专属分支。
