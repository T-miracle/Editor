# 04 — 在设置界面配置插件并按作用域热生效

**Status:** ready-for-agent — 已发布，未开始实现；须等待全部阻塞项完成

**GitHub:** [#5](https://github.com/T-miracle/Editor/issues/5)

**Parent:** [设计基线 #1](https://github.com/T-miracle/Editor/issues/1)

## What to build

示例插件通过声明生成基础设置界面，显示有效配置来源；用户确认的项目值覆盖全局值，错误配置被明确指出。

在真实读写、校验和显示流程中落实配置类型、默认值与生效方式，后续语言服务直接消费这套配置。

## Acceptance criteria

- [ ] 插件声明配置类型、默认值、作用域与热生效方式，宿主用现有原生控件生成基础设置。
- [ ] 优先级为已确认项目值、用户全局值、自动发现值、声明默认值；界面能说明生效值来源。
- [ ] 动态钩子可以校验或补全未指定项，不能替换用户显式指定但无效的值。
- [ ] 配置变化即时生效或仅重启示例实例；不重启宿主。
- [ ] 项目配置不能覆盖授权、信任及不允许项目覆盖的编辑器用户级设置。
- [ ] 配置持久化和再次打开工作区后保持一致，验证失败不破坏上一次可用配置。

规格验收覆盖：T23。

## Implementation guardrails

- 使用已确认的现有包管理器与编辑器集成测试边界，不新增插件专属测试入口。
- 只改变本工单范围，保留工作区已有改动；新增代码同时补充意图和不变量注释。
- 复用既有模块；必要的预重构先保持行为不变并通过相关回归，再加入新行为。
- 测试使用隔离目录与夹具，不操作用户真实插件安装数据；不提交 Git、不发布中间版本。
- 流程与契约细化若改变已确认产品行为，应先评审；不能以实现方便引入插件专属分支。
