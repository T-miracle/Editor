# 07 — 用可选 WASM 钩子启动未知语言的 LSP

**Status:** completed — 已实现并通过测试及双轴审查，随提交推送关闭 GitHub #8

**GitHub:** [#8](https://github.com/T-miracle/Editor/issues/8)

**Parent:** [设计基线 #1](https://github.com/T-miracle/Editor/issues/1)

## What to build

未知语言插件使用用户指定的本机测试 LSP，按需运行配置钩子；安装后已打开文档即可获得诊断和至少一种导航或补全结果。

把服务初始化、配置节与项目发现从具体语言业务中抽离。消费已完成的配置、语言贡献和受管进程能力。

## Acceptance criteria

- [x] 声明式服务定义支持可选 WASM 项目发现、路径解析、启动和初始化配置钩子，输入输出及就绪判定明确。
- [x] 宿主管理标准输入输出 JSON-RPC、文档打开/变更/关闭同步、请求取消及服务退出，插件不实现整套客户端。
- [x] LSP 提供者可与识别、高亮提供者不同；默认每份文档一个 LSP，遵守项目选择及候选变更规则。
- [x] 已打开和未保存文档正确同步，旧 revision、旧实例和已移除提供者的结果被丢弃。
- [x] 用户显式配置错误直接报告，不偷偷替换程序；配置更新只重启受影响服务。
- [x] 测试服务器能观察插件生成的初始化与配置响应；宿主不识别特定语言或服务器名称。

## Implementation guardrails

- 使用已确认的现有包管理器与编辑器集成测试边界，不新增插件专属测试入口。
- 只改变本工单范围，保留工作区已有改动；新增代码同时补充意图和不变量注释。
- 复用既有模块；必要的预重构先保持行为不变并通过相关回归，再加入新行为。
- 测试使用隔离目录与夹具，不操作用户真实插件安装数据；不提交 Git、不发布中间版本。
- 流程与契约细化若改变已确认产品行为，应先评审；不能以实现方便引入插件专属分支。
