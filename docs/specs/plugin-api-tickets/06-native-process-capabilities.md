# 06 — 按权限启动声明服务与交互式进程

**Status:** ready-for-agent — 已发布，未开始实现；须等待全部阻塞项完成

**GitHub:** [#7](https://github.com/T-miracle/Editor/issues/7)

**Parent:** [设计基线 #1](https://github.com/T-miracle/Editor/issues/1)

## What to build

示例插件能启动获批的标准输入输出服务，另一个明确获授任意命令权限的示例能启动交互式进程；越权启动失败，停用后进程退出。

将现有进程与 PTY 实现接到新类型化能力和资源归属。保留非 PTY 标准管道路径，为 LSP 提供正确传输。

## Acceptance criteria

- [ ] 以可执行路径和参数数组启动，区分标准输入输出进程与 PTY，不把 LSP 强制放入 PTY。
- [ ] 启动声明服务与任意命令执行使用不同授权范围；声明服务的实际程序与参数边界不能由未授权路径替换。
- [ ] 进程输入、输出、退出、尺寸和关闭具有类型化语义，实例拥有进程及其后代资源。
- [ ] 原生安装脚本尚未开放；普通服务权限不能借此执行任意安装步骤。
- [ ] 安装集中确认权限，更新增加权限重新确认；拒绝新增权限保留旧版本授权与可用性。
- [ ] 受限工作区拒绝执行；退出、取消和停用产生明确结果，原生程序权限边界在界面如实说明。

## Implementation guardrails

- 使用已确认的现有包管理器与编辑器集成测试边界，不新增插件专属测试入口。
- 只改变本工单范围，保留工作区已有改动；新增代码同时补充意图和不变量注释。
- 复用既有模块；必要的预重构先保持行为不变并通过相关回归，再加入新行为。
- 测试使用隔离目录与夹具，不操作用户真实插件安装数据；不提交 Git、不发布中间版本。
- 流程与契约细化若改变已确认产品行为，应先评审；不能以实现方便引入插件专属分支。
