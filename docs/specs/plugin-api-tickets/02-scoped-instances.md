# 02 — 在工作区内隔离插件实例并回收资源

**Status:** ready-for-agent — 已发布，未开始实现；须等待全部阻塞项完成

**Parent:** [设计基线 #1](https://github.com/T-miracle/Editor/issues/1)

## What to build

同一示例插件在两个逻辑工作区保持独立数据与状态；关闭工作区或禁用插件后，相关资源归零。显式应用级示例可跨工作区继续运行。

沿现有实例与资源句柄边界建立归属，不增加多窗口产品功能。为后续进程、订阅和服务提供统一拥有者。

## Acceptance criteria

- [ ] 声明工作区或应用级实例作用域，默认工作区隔离；声明式主题等资源不强制启动空 WASM 实例。
- [ ] 提供带作用域的类型化工作区读取、私有数据读取和写入能力；用户级设置与项目数据不混用。
- [ ] 资源句柄绑定实例和作用域，跨实例或失效句柄请求明确拒绝。
- [ ] 禁用、卸载和工作区结束后拒绝新请求、撤销界面并释放已拥有资源；应用级实例遵守独立生命周期。
- [ ] 包和依赖缓存可以共享，但运行状态不能因共享缓存而串用。
- [ ] 受限工作区不能启动插件、读取受限资源或以项目设置授予权限。

## Verification

使用两个隔离临时工作区和一个应用级夹具，验证读写隔离、权限拒绝、实例结束后的句柄失效及可见资源回收。

规格验收覆盖：T16、T17、T22。

## Implementation guardrails

- 使用已确认的现有包管理器与编辑器集成测试边界，不新增插件专属测试入口。
- 只改变本工单范围，保留工作区已有改动；新增代码同时补充意图和不变量注释。
- 复用既有模块；必要的预重构先保持行为不变并通过相关回归，再加入新行为。
- 测试使用隔离目录与夹具，不操作用户真实插件安装数据；不提交 Git、不发布中间版本。
- 流程与契约细化若改变已确认产品行为，应先评审；不能以实现方便引入插件专属分支。
