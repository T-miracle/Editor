## What to build

交付只使用新协议的主程序和插件包，保留用户数据；未知插件、现有插件及故障场景通过统一契约验收。

广域迁移的收缩与最终集成工单。删除旧运行形式，不删除数据升级所需的有限导入机制；全部迁移批次是硬性前置。

## Acceptance criteria

- [ ] 移除旧消息、字符串宿主命令、旧 UI 字段适配和运行转换入口，清理宿主固定语言与专属服务分支。
- [ ] 执行 T01–T26，覆盖独立陌生插件与实际插件；合理的发行清单、测试样例及命名空间数据不被误判为耦合。
- [ ] 当前包版本、SDK、公开契约和发行产物一致，旧协议包明确拒绝，用户数据与启用范围可迁移。
- [ ] 完成仓库格式、非 UI 测试、工作区编译和受影响 GPUI、真实包检查；Windows 行为实测与其他平台构建状态分别说明。
- [ ] 更新仍指导实现的规范、SDK 与用户文档，明确授权依赖下载、热更新边界及原生执行限制。
- [ ] 不得发布中间双协议开发状态；任何尚未满足的契约测试或恢复缺口都不能标记为完成。

## Implementation guardrails

- 使用已确认的现有包管理器与编辑器集成测试边界，不新增插件专属测试入口。
- 只改变本工单范围，保留工作区已有改动；新增代码同时补充意图和不变量注释。
- 复用既有模块；必要的预重构先保持行为不变并通过相关回归，再加入新行为。
- 测试使用隔离目录与夹具，不操作用户真实插件安装数据；不提交 Git、不发布中间版本。
- 流程与契约细化若改变已确认产品行为，应先评审；不能以实现方便引入插件专属分支。
