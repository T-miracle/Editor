# E07 — 用 GitHub Actions 部署到项目站并核验真实链接

**Status:** ready-for-agent — 本地制品，未发布 GitHub。稳定标识：`docs-site-07`

**规格：** [编辑器文档站点规格](../specs/docs-site.md)。覆盖用户故事：24、20。

## What to build

建立仓库的首条持续集成与部署流水线：安装依赖、运行站点测试与构建、发布到 GitHub Pages 项目站，并在真实子路径下核验页面与链接。同时补充仓库根 README 中"使用者文档以站点为准"的指引。

## Acceptance criteria

- [ ] 流水线在站点测试失败时不部署，不发布未通过检查的产物。
- [ ] 部署目标为项目站的真实 URL（带仓库名前缀），发布后中英两版路由均可直接访问，站点首页可达。
- [ ] 真实子路径下的资源与站内链接可用：抽查首页、栏目页、深层页面与语言切换，确认无因根路径前缀导致的 404。
- [ ] 部署产物为静态文件，不依赖运行时服务；搜索索引等构建产物随站点一同发布。
- [ ] 仓库根 README 增加指引：使用者文档以站点为准，本文件用于开发者；指向的 URL 与真实站点一致。
- [ ] 记录首次上线需用户在仓库设置中把 Pages 来源切到 GitHub Actions；未切换前不宣称已上线。

## Blocked by

## Verification

推送后读回流水线结果与部署状态，再用真实 URL 逐项打开页面与语言切换；核对页面源码中的资源路径确实带仓库名前缀。记录实际 URL、检查过的页面与结果，以及仍需用户操作的步骤。

## Implementation guardrails

- 不引入与站点无关的 CI 步骤；不在流水线中执行需要原生图形环境的编辑器测试。
- 不在仓库中保存任何凭据；使用平台提供的令牌机制。
- 不因部署方便而修改站点的导航、内容或根路径约定；根路径是已确认的部署形态。
- 保留工作区已有改动。
