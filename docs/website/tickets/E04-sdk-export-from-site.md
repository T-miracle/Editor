# E04 — 用站点源驱动 SDK 导出并回归分发验证

**Status:** ready-for-agent — 本地制品，未发布 GitHub。稳定标识：`docs-site-04`

**规格：** [编辑器文档站点规格](../specs/docs-site.md)。覆盖用户故事：12、13、21。

## What to build

把随编辑器分发的 SDK 文档来源从源码旁改为站点英文树，使插件作者通过 `--export-plugin-sdk` 或 `--plugin-cargo` 得到的文档与站点上发布的完全一致；并回归整条 SDK 分发链路，确认导出文件集合、内容摘要与损坏修复行为不变。

## Acceptance criteria

- [ ] SDK 导出的文件集合与迁移前相同：协议文档、WIT、Rust 源码与清单仍全部导出，不新增也不遗漏。
- [ ] 导出的协议文档内容取自站点英文树；中文页面不进入 SDK 载荷。
- [ ] 内容摘要缓存的既有语义不变：文档内容变化即产生新的摘要目录，旧摘要不被覆盖。
- [ ] 站点文档目录被移动或改名时，宿主构建失败并给出可定位的错误；这是有意建立的耦合，需在站点协作约定中明确写出警告。
- [ ] SDK 验证脚本在迁移后继续通过，包括导出、文件存在性、哈希一致性与损坏后修复；不修改脚本断言来迁就实现。
- [ ] 插件作者的独立构建路径（仓库外的访客项目经公开入口构建）不受影响。

## Blocked by

- E03 — 补齐能力协议的中文译文

## Verification

先构建宿主可执行文件，再运行 SDK 分发验证脚本；实际执行一次导出并检查文档内容与语言；制造一次站点文档改名，确认构建失败，随后还原。记录实际命令、结果与跳过项。

## Implementation guardrails

- 迁移采用纯搬迁方式：先建立路径耦合并验证 SDK 链路，再考虑任何清理，不在同一步混入行为改动。
- 不建立兼容分支或双源回退：文档来源只有站点一处。
- 修改资源引用时同步核对受影响注释；引用站点目录的代码需说明为何跨目录。
- 涉及真实组件的用例按其 ignore 原因先构建夹具再显式运行。
