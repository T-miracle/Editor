# 资源管理器外部粘贴、拖放与文件操作撤销规格

规格标识：`explorer-file-transfer`

整理日期：2026-10-07。

状态：产品交互与测试接缝均已确认；已发布为 GitHub [#76](https://github.com/T-miracle/Editor/issues/76)。三张实施工单已完成代码实现，正在核对最终原生验收与审查；实际通过范围见[验收记录](../verification/explorer-file-transfer.md)。

## Problem Statement

用户需要把系统文件管理器中的文件和目录导入项目，并通过资源目录树整理项目内的文件位置。现有资源管理器已经具备右键粘贴的复制基础，但尚未形成完整的文件转移交互：不能从目录树拖动文件，不能完整遵循外部剪切状态，缺少批量冲突选择、后台进度、取消及文件操作撤销。

文件转移还会影响已打开标签页及未保存内容。用户需要移动后继续编辑原有文档，在同名覆盖、中途失败以及撤销冲突时获得明确反馈，并自行决定是否执行可能丢失后续修改的强制撤销。

本规格综合本次访谈中已经作出的选择，不新增产品访谈，也不把当前实现的限制当作预期行为。

## Solution

在资源管理器中提供统一的文件复制、移动与冲突处理体验：外部文件和目录可以批量粘贴、拖入，树内可以单项拖动，落点对应实际目标目录。复制和移动在后台执行，长操作提供进度与取消，失败信息使用通用消息提示展示。

移动文件或目录时，同步已打开标签页的路径，并保留文档编辑状态。对普通替换保护未保存内容；对用户明确选择的强制撤销，在再次说明数据丢失并确认后允许丢弃相关未保存内容。

提供当前会话内的文件操作撤销与重做，通过右键菜单和目录树焦点下的快捷键触发。Windows 完整实现并验收，尽量复用跨平台能力保持 macOS/Linux 可用，分别记录实际支持和验证范围。

## User Stories

1. 作为编辑器用户，我希望复制外部文件后粘贴到资源目录树，以便把已有文件导入项目。
2. 作为编辑器用户，我希望剪切外部文件后粘贴时执行移动，以便遵循系统文件管理器的操作意图。
3. 作为编辑器用户，我希望一次粘贴多个文件和目录，以便批量导入资料。
4. 作为编辑器用户，我希望把外部文件和目录拖入资源目录树，以便直接选择导入位置。
5. 作为编辑器用户，我希望外部拖入默认复制，以便保留外部原文件。
6. 作为编辑器用户，我希望拖动树内单个文件到其他目录，以便调整其磁盘位置。
7. 作为编辑器用户，我希望拖动树内单个目录，以便整体移动其中的内容。
8. 作为编辑器用户，我希望树内拖动时按住复制修饰键可以复制，以便通过同一手势选择复制或移动。
9. 作为编辑器用户，我希望拖动时显示当前复制或移动意图，以便在放下前核对操作。
10. 作为编辑器用户，我希望拖放到目录行时写入该目录，以便落点与实际目标一致。
11. 作为编辑器用户，我希望拖放到文件行时写入该文件的父目录，以便不必精确寻找父目录行。
12. 作为编辑器用户，我希望拖放到树的空白处时写入项目根目录，以便方便地导入顶层内容。
13. 作为编辑器用户，我希望粘贴采用与拖放一致的目标解析规则，以便不必记忆两套行为。
14. 作为编辑器用户，我希望拖动时高亮实际目标目录，以便避免放错位置。
15. 作为编辑器用户，我希望目录树获得焦点时才能触发文件粘贴快捷键，以便编辑区仍能正常粘贴文本。
16. 作为编辑器用户，我希望拖动悬停折叠目录约 600ms 后自动展开，以便进入深层目录。
17. 作为编辑器用户，我希望拖动靠近目录树上下边缘时自动滚动，以便到达当前不可见的目标。
18. 作为编辑器用户，我希望取消拖动后恢复本次临时展开状态，以便保持原有目录布局。
19. 作为编辑器用户，我希望同名冲突时可以选择跳过，以便保留目标原有内容。
20. 作为编辑器用户，我希望同名冲突时可以选择保留两份，以便同时保存来源与目标内容。
21. 作为编辑器用户，我希望同名文件冲突时可以明确选择替换，以便更新项目内文件。
22. 作为编辑器用户，我希望冲突决定可以应用于本批后续冲突，以便减少重复确认。
23. 作为编辑器用户，我希望同名目录可以经确认后合并，以便保留目标独有文件并导入新增内容。
24. 作为编辑器用户，我希望合并目录中的同名文件继续按冲突规则处理，以便不发生静默覆盖。
25. 作为编辑器用户，我希望移动已打开文件后标签页同步更新路径，以便继续编辑同一文档。
26. 作为编辑器用户，我希望移动目录时同步更新其中所有已打开文件的路径，以便标签页不再指向旧位置。
27. 作为编辑器用户，我希望移动时保留未保存内容、光标和文本撤销记录，以便整理目录不打断编辑。
28. 作为编辑器用户，我希望普通替换禁止覆盖有未保存修改的目标文件，以便不丢失编辑中的内容。
29. 作为编辑器用户，我希望长时间复制或移动在后台执行，以便继续使用编辑器。
30. 作为编辑器用户，我希望长操作显示进度并允许取消，以便了解进展并中止误操作。
31. 作为编辑器用户，我希望失败或取消后保留已完成项、清理当前未完成结果，以便知道哪些内容已经实际转移。
32. 作为编辑器用户，我希望操作失败后停止后续项并报告成功、失败和未执行项，以便核对结果并决定如何重试。
33. 作为编辑器用户，我希望通用消息提示展示失败路径和具体原因，并保留到手动关闭，以便有时间处理问题。
34. 作为编辑器用户，我希望导入时跳过符号链接和 Windows 目录联接并提示跳过项，以便继续导入普通文件而不递归进入链接目标。
35. 作为编辑器用户，我希望通过右键菜单或快捷键撤销文件操作，以便恢复移动路径、移除复制结果或恢复被替换文件。
36. 作为编辑器用户，我希望通过右键菜单或快捷键重做，以便恢复刚才撤销的文件操作。
37. 作为编辑器用户，我希望目录树与编辑区根据焦点分别处理文件撤销和文本撤销，以便快捷键作用明确。
38. 作为编辑器用户，我希望当前会话保留文件操作记录和备份，并在退出后清理，以便获得会话内恢复能力且不把备份留在项目中。
39. 作为编辑器用户，我希望撤销发现后续修改或路径占用时逐项确认，以便决定是否强制撤销。
40. 作为编辑器用户，我希望强制撤销涉及未保存内容时再次明确确认，以便知晓并主动接受丢弃修改的结果。
41. 作为编辑器用户，我希望重做前重新检查路径和冲突，以便不会盲目重放已经过期的操作。
42. 作为 Windows 用户，我希望文件剪贴板、拖放、冲突及撤销流程经过完整验收，以便可靠地整理项目。
43. 作为 macOS/Linux 用户，我希望能使用可复用的平台能力，并获知实际支持范围，以便不把编译通过误认为功能已完整验收。

## Implementation Decisions

### 操作范围与目标

- 支持外部文件、目录的多项粘贴和拖入；目录树自身继续单选，不新增 Ctrl/Cmd 多选或 Shift 连选。
- 树内拖动改变实际文件位置，不实现手工调整显示排序。
- 外部粘贴遵循系统的复制或剪切意图；当前只复制的实现不能作为最终行为。
- 外部拖入默认复制；树内拖动默认移动，Windows/Linux 按住 Ctrl、macOS 按住 Option 时切换为复制。
- 目录行解析为该目录，文件行解析为父目录，空白处解析为项目根目录；粘贴与拖放共用此规则。
- 拖动时展示操作意图并高亮实际目标目录。
- 文件粘贴快捷键仅在目录树获得焦点时生效，不截获编辑区的文本粘贴。

### 拖动中的目录导航

- 悬停折叠目录约 600ms 后自动展开。
- 靠近目录树上下边缘时自动滚动。
- 取消拖动后恢复本次临时展开的目录；不要把用户原有的展开状态一并折叠。
- 原有单击选择、双击打开文件、双击目录或单击箭头展开/折叠的交互继续有效。

### 冲突选择与目录合并

- 同名冲突提供“跳过”“保留两份”“替换”，并允许把选择应用于本批后续冲突。
- 保留两份产生不覆盖已有内容的新名称；具体命名形式尚未在访谈中指定。
- 同名目录经用户选择后采用合并，不删除目标目录独有文件。
- 目录内部同名文件继续进入冲突流程；目录合并不是静默覆盖授权。
- 普通复制、移动和替换遇到有未保存修改的目标文件时，禁止覆盖，并提供跳过或保留两份的选择；用户可先自行保存或关闭相关标签页。

### 文档与标签页一致性

- 允许移动正在编辑、尚未保存的源文件。
- 成功移动后更新标签页路径，保留未保存内容、光标与已有文本撤销记录。
- 移动目录时，同步更新其内部已打开文件的路径。
- 继续以 EditorState 作为内存文本、选择、布局和文本 Undo/Redo 的唯一来源，不维护第二份可变文本或文本撤销栈。
- 文件操作的撤销记录描述磁盘操作及其备份，与文档的文本撤销记录分开处理。
- 资源目录树、标签页及文档状态应反映实际完成的结果；失败项和未执行项不能被标记为已成功移动。

### 后台任务、取消与失败

- 文件复制和移动在后台执行，耗时较长时显示进度和取消按钮，编辑器仍可使用。
- 中途失败时保留已完成项，清理当前未完成的复制结果，停止后续操作，区分成功、失败和未执行项。
- 用户取消采用同样的部分完成处理方式，不承诺自动撤销整批已完成操作。
- 清理仅针对本次未完成结果；目录合并不能把目标原有内容当作临时结果删除。
- 已完成结果仍属于本次文件操作记录的事实依据；不能在操作部分失败后报告整批成功。
- 报错使用本地通用消息提示，展示具体失败路径和原因，并保留到手动关闭。
- 普通定位提示维持原有 1.2 秒自动隐藏行为；文件操作错误不沿用该时长。
- 导入时跳过符号链接和 Windows 目录联接，不跟随链接递归复制；结束后通过通用消息提示汇总跳过项。这是已确认的跳过规则，不按普通复制失败停止整批。

### 文件操作撤销与重做

- 本次支持复制、移动、替换及目录合并产生的文件转移结果的撤销与重做；不扩展为其他资源管理器命令的通用撤销工程。
- 撤销移动恢复原路径；撤销复制移除本次复制结果；撤销替换恢复被替换文件。目录合并需要区分新增内容、被替换内容和原有未变内容。
- 右键菜单提供“撤销文件操作”和“重做文件操作”，并表达具体操作对象，避免与文本撤销混淆。
- 目录树有焦点时，Ctrl+Z 撤销文件操作，Ctrl+Shift+Z 重做文件操作；编辑区有焦点时对应快捷键继续处理文本编辑。
- 记录与备份仅在当前编辑器会话内有效，备份位于项目目录之外，退出后清理记录及备份。
- 撤销前检查操作后文件是否发生变化、原路径是否被占用等冲突。
- 撤销遇到后续变化时逐项弹窗确认，允许用户选择强制撤销并覆盖后续变化。
- 强制撤销涉及未保存内容时，必须再次明确说明将丢失未保存修改；只有再次确认后才允许丢弃相关内容并撤销。
- 强制撤销是用户明确批准的例外，不得据此放宽普通替换的未保存内容保护。
- 重做前重新检查路径、文件状态及冲突，不能直接重放旧路径假设。

### 模块边界与原生 UI

- 在现有资源管理器、文件操作、文档会话及平台输入接缝内扩展，不为每种入口建立独立的复制与移动策略。
- 右键菜单、快捷键和拖放应汇入共同的操作语义，以便目标解析、冲突处理、错误反馈及撤销结果保持一致。
- 继续复用 GPUI 的行为与状态接口；菜单、冲突确认、进度、拖动反馈和消息提示使用项目本地 UI 外观与主题契约。
- 保留中英文资源、深浅主题及已有焦点规则；本次文件粘贴不得改变中文 IME 和编辑器文本粘贴行为。
- 遵守既有路径边界、规范化和资源生命周期要求，不复制上游控件源码、不 fork GPUI Kit。

### 平台交付

- Windows 完整实现并完成真实系统剪贴板、原生拖入及交互验收。
- 尽量复用跨平台文件操作和 GPUI 输入能力，保持 macOS/Linux 可用；明确记录未支持、仅可编译及实际运行验收的区别。
- 代码调查显示三端已有外部文件拖入事件接缝，Windows/macOS 已有外部文件剪贴板读取基础，当前 Linux 依赖的文件剪贴板读取仍存在缺口。
- 系统剪切意图需要单独核对和适配；不能把读取到文件路径等同于已经识别复制或剪切。

## Testing Decisions

### 已确认的主要测试接缝

复用现有资源管理器 GPUI 交互测试作为唯一主要的应用层行为入口：挂载真实 EditorApp 与资源目录树，使用临时工作区、实际文档会话和磁盘文件，从菜单、快捷键以及拖放事件触发操作，然后检查磁盘结果和可观察 UI 状态。

用户于 2026-10-07 确认该测试方案，并确认补充 Windows 系统剪贴板与拖放的真实操作验收。该确认不把测试工具内部函数或私有状态结构规定为产品 API。

已有先例包括资源树单击与双击、目录递归折叠、标签定位、菜单实际目标、剪贴板写入、删除确认及消息提示的交互测试。继续借鉴这些先例，不为每种入口新建一套仅转发调用的测试接口。

原生操作系统剪贴板和拖放协议不能仅靠合成 GPUI 事件证明正确；Windows 需要补充从系统文件管理器进入编辑器的真实操作验收。其余平台按实际可用环境记录结果，不能以 Windows 结果代替。

| 撤销遇到后续修改或路径占用 | 撤销确认 | 显示具体冲突，仅按用户选择执行强制撤销 |
| 强制撤销遇到未保存内容 | 二次确认 | 拒绝确认时保留内容，明确再次确认后才丢弃 |
| 目录树与编辑区切换焦点 | 粘贴、撤销和重做快捷键 | 作用于文件或文本的目标正确，中文输入与文本粘贴不被截获 |
| 会话结束 | 关闭编辑器 | 清理本会话文件操作记录和项目外备份 |
| 明暗主题及平台差异 | 原生 UI 和平台验收 | 状态可识别，支持情况与验收记录一致 |

只断言用户能观察到的输入、磁盘变化、文档状态和 UI 反馈，不测试内部调用次数、特定容器类型或私有函数拆分。失败与取消应采用可控的时机，避免依赖随机磁盘速度。

实施阶段遵循仓库要求运行相关模块测试、资源管理器 GPUI 交互测试、Rust 格式检查、非 UI workspace 测试与 workspace 编译检查，并记录必要的 Windows 原生验收证据。本文档整理本身不等于这些测试已经执行。

## Out of Scope

- 目录树多选、Ctrl/Cmd 多选、Shift 连选及树内批量拖动。
- 仅改变树显示顺序而不改变磁盘位置的手工排序。
- 从编辑器向外部程序拖出文件的能力。
- 跟随导入目录中的符号链接或目录联接复制目标内容。
- 重启后恢复文件操作撤销记录或备份。
- 为现有新建、删除等其他文件命令一并补齐通用撤销能力。
- 把文件操作撤销与文档文本撤销合并为同一个可变撤销栈。
- 中途失败后无条件自动回滚整批已经完成的操作。
- 把本规格发布或整理视为实现、测试、提交、推送或关闭工单已经完成。
