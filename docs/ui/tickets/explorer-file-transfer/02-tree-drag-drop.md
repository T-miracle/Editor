# 02：目录树拖放与目标导航

稳定标识：`explorer-file-transfer-02`。状态：已批准并发布，待实施。

## Parent

[资源管理器文件转移规格 #76](https://github.com/T-miracle/Editor/issues/76)。设计依据，不作为必须关闭的执行阻塞项。

## What to build

用户可在目录树内拖动单个文件或目录改变磁盘位置，也可从系统文件管理器批量拖入内容。拖动时可看到操作意图和目标，悬停展开目录、靠近边缘滚动，到达深层目录后放下即执行。

拖放进入已有公共文件转移流程，直接复用冲突处理、后台进度、取消、文档同步、错误提示和完成记录。

## Acceptance criteria

- [ ] 树内单项拖动默认移动；Windows/Linux 按住 Ctrl、macOS 按住 Option 时复制，并显示操作意图；继续保持树内单选。
- [ ] 支持外部文件和目录多项原生拖入，默认复制；落在资源树上不误触发编辑区其他拖入行为。
- [ ] 目录行、文件行和空白处沿用公共目标规则，高亮实际目标目录，无效目标不能执行。
- [ ] 悬停折叠目录约 600ms 自动展开，靠近上下边缘自动滚动；离开目标后旧计时不错误展开原目录。
- [ ] 取消拖动恢复本次临时展开状态，保留原有展开状态；取消不得执行文件转移。
- [ ] 拖动识别不破坏单击选择、双击打开、目录箭头及右键菜单交互。
- [ ] 放下后复用工单 01 的冲突、合并、未保存内容保护、后台进度、取消及错误提示流程，不建立第二套规则。
- [ ] 成功移动同步已打开标签路径和编辑状态，使用公共完成记录与备份机制，使操作能被入口无关的撤销流程消费。
- [ ] 通过 GPUI 输入测试验证修饰键、落点、可控悬停时间、滚动及取消，检查真实磁盘与标签结果。
- [ ] 完成 Windows 系统文件管理器到目录树的原生拖入验收，以及明暗主题反馈检查；记录其他平台实际支持及未验收项。
- [ ] 只补拖放特有场景和代表性公共流程接入验证，不复制完整冲突/失败组合；通过相关测试及仓库规定的阶段检查。

## Testing decisions

本票重点验证输入手势、目标反馈、悬停和滚动，以及拖放接入公共流程的正确性。复用粘贴的应用挂载与工作区夹具，用代表性冲突和失败证明接入，其余公共语义沿用工单 01 的覆盖。

不依赖工单 03 的菜单或快捷键。跨入口撤销/重做的联合场景在 02、03 均完成后集中验证。
