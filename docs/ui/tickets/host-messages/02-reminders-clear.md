## What to build

宿主有新的警告或错误时，底部消息按钮的通知图标上显示红色圆点；普通消息不提醒，消息到达不会自动展开窗口或抢焦点。用户打开窗口即可清除当时已有红点，无须逐条查看或展开所有消息，后续警告或错误仍能再次提醒。

用户点击“清空消息”即可清除当前全部宿主记录和红点，立即得到可继续接收新消息的空列表；插件日志及其提醒不受影响。在工单 01 的真实窗口和历史基础上，完成“异常 → 提醒 → 打开确认 → 清空 → 接收新消息”的闭环，并做一次简短组合验收。

## Acceptance criteria

- [x] 新宿主警告或错误在指定通知图标上产生红色圆点，普通消息不产生红点；不替换为计数徽标、弹窗或声音。
- [x] 无论窗口是否已显示，新消息都不抢编辑焦点、不自动改变显隐；普通重绘不能自行抹掉新提醒。
- [x] 用户打开窗口清除已有红点，保留消息，不要求滚动到所有记录、逐条点击或展开全部历史。
- [x] 打开只确认当时已到达的提醒；之后的新警告或错误再次产生红点，迟到确认不能吞掉新消息提醒。普通消息不能错误清除已有红点。
- [x] “清空消息”通过原生按钮一次清除全部宿主历史和已有红点，空状态中不存在失效的查看更多入口；后续新消息正常显示并按等级触发提醒。
- [x] 清空与新消息交错时，不丢失清空之后到达的消息，也不复活已经清空的记录；批量展开、500 条淘汰和红点确认之间不互相冒充用户确认。
- [x] 插件消息不触发宿主红点；打开或清空宿主窗口不改变插件日志、插件已读状态及插件提醒。
- [x] 重启不恢复旧消息或红点，同时保留工单 01 的布局与显隐行为。
- [x] 红点及清空按钮在深浅主题中可辨识，中英文文本及键盘操作正常；新增代码包含原因、确认边界和生命周期注释。
- [x] 复用工单 01 的应用级夹具增加提醒、确认、清空及隔离回归，不复制整套列表和布局测试。最后只做一次跨功能短组合验收，并核对规格所有场景都有对应证据。
- [x] 交付前执行仓库规定的格式、非 UI workspace 测试、workspace 编译检查，以及受影响的 editor-app 测试和必要 Windows 原生交互验收；记录实际结果，缺失环境或未执行场景不得标为通过。

## Verification

- 主负责规格 M11–M15，以及 M03 的提醒隔离、M09 的红点生命周期、M16 的红点与清空交互。
- 在同一 GPUI 窗口验证普通消息、警告、错误的区别，真实点击消息按钮和清空按钮，观察红点、列表、显隐及编辑焦点。
- 重点增加“打开后再到达”“确认回调迟到”“清空后再到达”和“宿主操作不改动插件日志”场景，不断言私有队列结构或方法调用次数。
- 组合验收使用一条流程：宿主异常 → 红点 → 打开 → 展开历史 → 清空 → 新警告 → 收起及重开 → 重启确认布局保留且历史不保留。
- 工单 01 未被修改的手工详细场景引用已有证据，不再全量重演；若本单改动影响消息来源、列表、容量或布局，则重跑对应回归，不能把旧结果宣称为当前版本刚测试通过。
- 当前没有必须独立执行的广域重构。若为增加确认与清空边界需要小范围预重构，先保持行为不变并验证，再加入新行为，不扩展为插件日志重构。
