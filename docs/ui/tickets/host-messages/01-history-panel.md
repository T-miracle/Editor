稳定标识：`ui-host-messages-window:ticket:01`

状态：实现、针对性回归、Windows 原生验收与双轴审查已完成；分支已推送，GitHub #85 已核对关闭。记录见 [实施验收](../../verification/host-messages.md)。

## Parent

[宿主消息窗口规格 #84](https://github.com/T-miracle/Editor/issues/84)

## What to build

用户执行宿主操作后，可以在主窗口右侧的原生消息窗口查看操作结果、警告和错误。所有宿主消息合为一个列表，最新在上，先展示 20 条并按 20 条逐批展开，当前运行最多保留 500 条。

用户可以收起窗口，通过底部使用指定通知图标的按钮重新打开，并在重启后恢复布局、宽度与显隐状态；历史消息不跨重启保存。插件消息继续留在插件日志管理，高频状态和调试输出不进入宿主消息历史。

该单交付完整的“宿主事件 → 消息历史 → 原生窗口 → 浏览与布局恢复”路径。红点提醒和清空操作在工单 02 交付；不能将本单完成表述为整个功能验收完成。

## Acceptance criteria

- [x] 消息组件是宿主自带面板，不需要插件或新增独立操作系统窗口，首次默认位于主窗口右侧。
- [x] 盘点并接入现有宿主面向用户的操作结果、警告与错误入口，记录实际覆盖及排除项；至少通过真实操作成功与失败场景证明消息从来源进入可见窗口，不能只展示测试注入数据。
- [x] 普通、警告、错误等级由消息来源明确给出；高频光标、实时进度及内部调试输出不进入历史，普通重绘不产生重复消息。
- [x] 插件消息，包括宿主代为报告的插件相关日志，仍归插件日志管理，不进入宿主窗口；不改动插件公开契约与日志历史规则。
- [x] 一个不分组的列表，按接收顺序倒序排列，相同时间下仍有确定顺序；初始最多 20 条，不足时全部展示。
- [x] “查看更多...”是文本按钮，每次追加最多 20 条更早记录，不替换已展开内容；全部展开后隐藏按钮。覆盖 0、1、20、21、40、41 条边界。
- [x] 所有消息等级共用 500 条容量，超出时只移除最早记录。展开期间继续接收和淘汰消息时，无重复、失效条目或超出容量边界的展开。
- [x] 收起回收编辑空间，消息不丢失；底部按钮使用用户提供的通知 SVG，重新打开可继续查看消息。
- [x] 复用现有停靠和会话机制保存布局、宽度及显隐；旧布局补入新面板时保留其他面板安排；重启不恢复消息历史。
- [x] 消息接收不抢焦点、不自动展开窗口；受限工作区可使用宿主消息组件，不因此启动插件或语言工具。
- [x] 本单新增 UI 采用本地控件外观和 gpui-base 行为基座，中英文、深浅主题、键盘操作、滚动与缩放可用；新增代码同时说明职责、边界和状态不变量。
- [x] 使用已确认的 GPUI 应用级入口完成针对性回归及必要 Windows 原生交互验收；交付前执行仓库规定的格式、非 UI workspace 测试和 workspace 编译检查，记录命令、结果和未验证项。
