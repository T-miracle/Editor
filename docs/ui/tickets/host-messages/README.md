## 预重构与范围

- 现有宿主状态和即时提示入口较分散；01 先在所属功能中完成必要的行为保持整理，再接入集中消息记录。保留已有状态展示语义，不通过重绘扫描状态字符串推断新消息。
- 已有 DockArea、宿主面板、会话恢复和本地控件可复用，没有证据要求单独进行广域机械重构。小范围预重构放在所属工单最前面，不额外增加交付阶段。
- 两单都包含所需状态、宿主接入、UI 和行为测试；01 可以独立演示浏览历史，02 可以独立演示异常提醒及清空。
- 没有插件协议或包变更，不安排 SDK 发布和包重打包工单。实现发现确需改变公开契约时，应重新核对范围，不能顺手扩大。
- 任一工单完成不等于整项功能完成；两单验收证据齐备后才可宣称功能交付。

## 减少重复测试

1. 每单开发中先运行受影响的针对性测试；交付前集中执行一次规定的阶段检查，不为每个控件反复跑全量命令。
2. 仓库要求仍保留：`cargo fmt --check`、`cargo test --workspace --exclude editor-app`、`cargo check --workspace`。两单对应两个交付阶段，不拆成更多检查批次，也不跳过每阶段必须执行的检查。
3. editor-app 的受影响测试与必要 Windows 原生交互验收随本单执行，明确记录场景归属、实际命令和结果。
4. 共用测试夹具、隔离工作区及构建产物。01 的未受影响手工场景在 02 引用已有记录，避免全矩阵再次手工重演；02 只新增提醒、清空与一次组合验收。
5. 新改动影响先前路径、出现失败或存在未解决风险时，必须重跑对应回归；不能用旧记录代替受影响行为的当前验证。
6. 不单独拆“测试与收尾”工单。文档、注释、相关回归和验收记录跟随对应功能交付；没有新增变化时，不重复已经通过的相同检查。
