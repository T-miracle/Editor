## 测试入口与减少重复

测试入口沿用方案：真实插件包安装到隔离工作区，经公开管理和语言接口验证实际文档与原生 UI。用户已要求发布并执行全部工单，批准该测试入口和三单拆分。

| 验收编号 | 主责任工单 | 执行边界 |
| --- | --- | --- |
| T01–T06、T21、T22 | 01 | 完整语言/Schema/依赖及 Image 组合；后续未改相关逻辑则引用记录 |
| T07–T14 | 02 | 格式化选择与 XML/HTML 编辑事务；不复制 01 的完整语言验证 |
| T15–T20 | 03 | 大纲、折叠、图标、四向停靠和布局恢复 |
| T23–T26 | 各单按增量负责 | 只新增本单能力的通用性、生命周期、UI、SDK/打包验证；不是每单再跑一遍全部产品场景 |

具体执行原则：

1. 每单开发中先跑受影响的针对性测试，完整交付检查集中在该单完成时。修复造成新影响时重跑对应检查，不为每个函数、契约字段或文档修改重复全量测试。
2. 仓库要求的每阶段检查仍执行：`cargo fmt --check`、`cargo test --workspace --exclude editor-app`、`cargo check --workspace`。减少拆单降低阶段数量，不把“减少重复”解释为跳过这些检查。
3. 修改宿主应用追加相关 GPUI 测试和原生交互验收。实际 WASM/ignored 测试按现行夹具构建要求显式运行，未执行不能算通过。
4. 共用隔离安装、可控服务和实际包夹具；输入、构建配置和工具版本未变时复用构建产物，不反复清理再编译。私有运行数据按场景隔离，不能因复用而污染结果。
5. SDK 变更仍做规定的分发验证；一次准备可供同单多个场景使用。消费者或 SDK 有变更时重新验证，不能拿旧二进制证明新契约正确。
6. 每单记录验证对应的提交/工作树和包身份、命令与结果。引用前单证据前检查本单是否影响相应路径；有影响才追加回归，不宣称旧结果就是新版本的通过结果。
7. 不单独增加“最终测试工单”。全部切片合齐后，由最后交付的一单执行一次短组合验收：打开 SVG、格式化、标签修改、验证大纲定位与预览响应、Undo/Redo，再验证工作区布局恢复。复用 T01–T26 已有详测证据，只检查跨功能组合，不完整重演所有矩阵。
8. 不把 02 未完成作为 03 独立交付的阻塞。如果 03 先完成，只验收自身功能；整批完成状态必须等全部三单及最后短组合验收满足。
9. 没有新增改动、失败或未解决风险，不重复已经通过的相同检查。预重构的行为保持测试、每阶段交付检查和实际风险回归仍保留。
