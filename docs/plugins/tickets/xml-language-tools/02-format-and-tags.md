## What to build

用户可格式化 XML，并为同一语言选择其他插件的格式化提供者，而不影响原有高亮、补全和诊断。用户还可在 XML、HTML 中主动重命名配对标签，或直接修改一端并自动同步另一端；修改保持正确的撤销和中文输入法行为。

将格式化和标签编辑合为一个“安全修改文档”切片，共用既有文档目标、revision 校验、事务与撤销边界；分别定义公开能力，不把二者强制绑定成一种提供者。完整交付通用契约、服务路由、选择设置、原生操作、XML/HTML 消费者及回归验证，不扩展大纲或停靠功能。

## Acceptance criteria

- [ ] 格式化提供者独立于主 LSP 和高亮选择，所有插件可通过同一公开接口贡献；替换格式化器不替换整套语言功能。
- [ ] 单一候选自动使用；多个候选保留有效选择，用户设置与项目设置可指定且项目优先，新安装不抢占。移除候选、显式配置错误及失败遵循方案与既有平台规则。
- [ ] 每次只调用一个选中格式化器；手动格式化可用，保存时格式化可选且默认关闭，不实现自动修复流水线。
- [ ] XML 格式化覆盖缩进、属性换行和空元素排版，保留混合文本及 xml:space 语义。
- [ ] 通过不同 ID 的替代格式化插件证明任意语言可复用；覆盖 JavaScript 默认提供者被替代的选择场景，不要求开发完整 ESLint 插件。
- [ ] XML、HTML 显式重命名使用常规新名称输入交互，只修改对应开始/结束标签，一次撤销恢复；不实现双端选区专用交互或跨文件重构。
- [ ] 直接编辑任意一端标签名时自动同步明确配对的另一端；默认开启，支持用户级关闭和按语言覆盖；配对不明只修改当前端。
- [ ] 同名嵌套、自闭合/HTML 空元素、属性和注释中的相似文本不被误改；规则由插件或其服务提供，宿主不按语言/插件 ID 配对。
- [ ] 格式化、重命名、关联编辑均通过唯一文档会话应用；过期、取消、关闭、重开或提供者失效的结果不写入文档，无部分错误提交。
- [ ] IME、粘贴、删除和 Undo/Redo 保持两端一致，无递归同步；不恢复已经撤回的双端选区 Enter/Esc 专用规则。
- [ ] 能力协商、权限、SDK 文档和独立消费者同步更新；修改 XML/HTML 包时同步提升版本并验证实际包，不新增旧协议兼容分支。
- [ ] 原生操作、设置及提示具有中英文、主题和键盘支持；新增代码补充用途与状态不变量注释。
