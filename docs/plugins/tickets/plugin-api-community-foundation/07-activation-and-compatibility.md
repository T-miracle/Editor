# 07：按需激活、配置热应用与兼容升级

稳定标识：`plugin-api-community-foundation-07-lifecycle`

状态：已批准，待实施；发布标签 `ready-for-agent`。实际设计议题及依赖编号见发布记录。

## What to build

安装本批插件后，用户可以看到可用命令与视图，但不必让所有插件立即运行。第一次使用命令、对应语言、视图或服务时按需激活；更改结构化配置、重载或升级插件时继续保持文档及私有数据安全。旧 SDK 插件可以按兼容规则运行或得到明确诊断，开发实例不污染正常配置。

本单交付真实的需求触发激活、配置变化与安全替换能力，并用前六单的完整资源类型完成一次组合验收；不是最后统一补 SDK、权限、清理或测试的工单。

## Acceptance criteria

- [ ] T31：命令/语言/视图/服务请求分别触发激活；静态贡献在实例启动前可发现；并发首次请求只创建一个实例，激活失败与取消可诊断。
- [ ] T32：结构化配置类型、校验、作用域、变化事件和适用的热应用可用；项目配置不能提升权限或覆盖用户语言/主题/信任，敏感值仍使用密钥能力。
- [ ] T33：声明式包不要求空 WASM；后台用途受预算/信任限制；退役后迟到结果不再应用，全部已交付资源和贡献清理。
- [ ] T34：稳定/实验能力、required/optional、最低宿主和迁移规则通过实际新旧 SDK 包验证；沿既有隔离开发、重载及失败恢复入口，不污染正常安装和私有数据。
- [ ] T35：完成一次全能力短组合，升级新增权限需确认、拒绝保留旧版、激活/提交失败保留受管数据，记录版本、产物和真实平台范围。
- [ ] 稳定兼容政策和实验说明对开发者可读，已拒绝历史协议仍明确拒绝；不存在“类型可协商但宿主未消费”的发布能力。
- [ ] 各前单实际验收证据完整，对与本单生命周期/配置变化相关的用例重跑，不把历史通过直接算当前新版本通过。
- [ ] 完成公共 C01–C06，并记录整批剩余限制；不自动发布软件版本或修改/关闭父设计议题。

## Blocked by

- 04：多来源诊断与语言修复闭环——用于语言需求激活、诊断撤销和修复过程的退役验证。
- 05：通用树与编辑器装饰——用于视图需求激活、节点异步响应和呈现资源替换验证。
- 06：云服务查询、密钥与后台刷新——用于服务/后台激活、配置变化以及网络/计时/密钥资源的恢复验证。

## 实施边界与预重构

先整理既有启动、启用及静态贡献注册边界，使“入口可见”与“实例运行”职责清晰，行为保持验证通过后再接需求激活。复用现有两阶段更新、实例唯一性、配置校验与开发控制器，不新建平行管理器。

在服务请求、语言和视图需求上处理循环/失败/取消及并发首次激活，保持可诊断与有界执行。配置只对适合热应用的能力直接生效，需要替换实例时遵循已有恢复约定，不笼统承诺所有配置都无重启生效。

每种能力的取消和清理已在前单成立；本单验证延迟启动和替换之后同样成立，不能容忍前单以“07 再补”为理由交付孤儿资源。

## 测试安排

主责 T31–T35。复用现有开发重载、热更新、作用域和配置测试，以及前单实际包；源码/SDK/清单未变时不反复构建同一包，运行数据仍隔离。

最终短组合：按需启动 → 读取未保存文档 → 两来源检查 → 预览多文件修改 → 整组撤销 → 树/装饰更新 → 云流取消 → 禁用清理 → 新增权限拒绝/失败升级恢复。它检验跨功能连接，不重新手工遍历前六单的每一种失败输入。

生命周期变化影响哪些资源，就重跑哪些既有清理和版本用例；配置或 SDK 变化影响消费者时重建并运行对应包。一次规定交付门禁与本单必要的 GPUI、原生交互、实际 WASM/系统设施验证仍完整执行，不将短组合当作全量质量替代。
