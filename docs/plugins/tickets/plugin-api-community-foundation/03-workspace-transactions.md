# 03：工作区文件操作与可撤销批量修改

稳定标识：`plugin-api-community-foundation-03-transactions`

状态：已批准，待实施；发布标签 `ready-for-agent`。实际设计议题及依赖编号见发布记录。

## What to build

项目脚手架与批量转换插件通过同一正式接口发现和管理文件、生成修改计划、预览确认并提交。已打开文档保持未保存，未打开文件按批准计划写入磁盘。用户可在当前会话明确撤销整组操作；冲突时停止，失败时知道哪些操作实际完成。

一个完整演示同时包含打开的脏文档、未打开文件、创建、改名和删除，再观察文件变化并整组撤销。另一个独立插件复用相同契约，证明不是某一种重构的专用 API。

## Acceptance criteria

- [ ] T11：单文档多范围事务通过 DocumentSession/EditorState，形成合理 Undo 单元；普通局部 Undo 不隐式修改其他文件。
- [ ] T12：stat、目录枚举、分页发现、创建目录、读写、复制、改名、删除及原子替换可用；工作区和用户选择的外部资源均校验授权，私有写入不冒充工作区写入。
- [ ] T13：混合文本与资源操作先预检/预览并确认，已打开文档不自动保存，未打开文件按计划落盘，不绕过脏缓冲区。
- [ ] T14：预览后文本或磁盘版本变化、目标关闭、越界、符号链接逃逸、设备路径和备用数据流均被正确处理；过期计划不能盲目覆盖。
- [ ] T15：当前会话内有独立的整组撤销入口；先检查全部目标，无冲突再恢复内容和资源状态，有后续修改或影响状态的局部 Undo 时停止整组自动撤销并列出冲突。
- [ ] T16：文件监听覆盖未打开文件、创建/修改/删除/改名、合并及溢出重扫；提交或撤销 I/O 失败、取消时明确已完成/失败/可恢复部分。
- [ ] 文本恢复始终使用唯一会话，不建立第二份可变文本或文档撤销栈；不承诺全磁盘原子回滚、取消自动回滚或跨重启整组 Undo。
- [ ] 完成公共 C01–C06，包含故障恢复说明、正式 SDK、实际包及 Windows 磁盘与原生文档验收。

## Blocked by

- 01：文档快照、事件与只读资源比较——提供资源身份、当前文本版本与事件。
- 02：插件命令、宿主交互与选择授权——提供外部选择授权、确认和进度入口。

## 实施边界与预重构

首先整理既有单文档格式化/Rename 的多范围校验与事务调用，使通用编辑消费者能够复用；先验证行为保持，再接跨文件计划。复用现有受控文件根、平台保存、本地历史与原生文档会话，不新建以磁盘内容代替打开文档的编辑模型。

每种文件操作明确针对打开文档时的处理及冲突结果，不能因为底层 OS 允许写入就绕开会话。整组协调信息记录操作归属与可恢复条件，不能接管各文档原生 Undo 栈。

本单内部不拆成“只定义协议”与“最后再接 UI”。需要先验证协调算法可满足唯一文档状态约束；若有产品行为冲突，报告具体场景，不削弱既定保存/撤销规则。

## 测试安排

主责 T11–T16；T01–T05、T08–T09 是可复用依赖用例。按当前差异重跑被改变的资源/授权路径，不复制其完整测试实现。

磁盘成功、后续编辑、文档关闭、局部 Undo、重命名链、I/O 中途失败和取消均以实际文件/缓冲区/可见结果断言。可控文件故障发生在现有平台边界，真实插件仍走正式计划入口。两个独立包完成一组脚手架和一组批量转换，实际 WASM 与原生预览/确认/撤销均需证据。

本单拥有事务与路径失败矩阵。04 仅新增“诊断修复调用此事务”连接测试；07 仅验证生命周期变化后的组合，不再手工重演全部磁盘故障。
