# 04：多来源诊断与语言修复闭环

稳定标识：`plugin-api-community-foundation-04-diagnostics`

状态：已批准，待实施；发布标签 `ready-for-agent`。实际设计议题及依赖编号见发布记录。

## What to build

用户同时启用拼写检查与配置检查，原生问题界面标明各自来源并能定位、预览和执行修复。插件无需运行 LSP 即可提供诊断。语言插件的引用查找、代码修复和函数参数提示进入原生编辑器，直接提供者与 LSP 复用结果呈现和编辑流程。

保留现有补全、格式化、单文档 Rename、关联编辑、结构与大纲；新增直接提供者以实验能力交付，不自动扩大为多 LSP 同时运行。

## Acceptance criteria

- [ ] T17：两个独立插件直接发布带 owner、严重程度、位置、关联信息、修复和 revision 的诊断；来源同时显示，各插件只能操作自己的集合。
- [ ] T18：修复通过正式编辑计划进入预览/确认/冲突校验；诊断旧版本、关闭或插件禁用后，动作不再可执行，结果和贡献正确清理。
- [ ] T19：引用查找、代码修复、函数参数提示有真实宿主消费者；两种独立语言场景验证直接提供者与 LSP 的共用导航/呈现/编辑路径。
- [ ] T20：补全、格式化、Rename/关联编辑、结构/大纲无回退；取消、切换提供者、关闭文档和过期结果不串目标，新直接能力明确实验版本和降级方式。
- [ ] 用户已有有效提供者选择不被安装顺序覆盖；多诊断源不隐式改变现有单 LSP 选择规则。
- [ ] 实际 LSP 能力矩阵、SDK、实验声明、错误和资源释放文档同步，不能仅有类型而无可用 UI。
- [ ] 完成公共 C01–C06，两个不依赖完整语言服务器的检查器和实际语言消费场景均从正式包入口验收。

## Blocked by

- 03：工作区文件操作与可撤销批量修改——提供修复所需的单文档/跨文件事务、冲突与撤销。

## 实施边界与预重构

先整理既有诊断及语言结果消费者，保留语义和测试，再让直接结果与 LSP 汇入相同路径。不新建第二套问题模型，不按语言名、服务器名或插件 ID 写业务分支。

新增提供者仅覆盖本单已确认的语言结果与必要接缝，不顺带实现全部高级语言特性、语义索引、行内 AI 补全或多 LSP 聚合。代码修复只声明业务修改，宿主事务决定如何安全应用。

## 测试安排

主责 T17–T20。复用纯语言补全、语言编辑、结构和 LSP 诊断先例。两种检查器验证跨来源归属与撤销，两种语言消费者验证实际结果，而非只验证回调被调用。

事务详测引用 T11–T16；本单新增单文件和跨文件修复各一个连接场景、一个 stale-revision 拒绝场景及实例退役场景。修改了共用事务代码时仍重跑相关 T11–T16，不因引用旧结果跳过回归。

Windows 原生验收覆盖问题定位、修复预览、引用导航、参数提示及键盘/焦点；现有完整语言测试按实际影响选择，不每次重新安装所有语言工具。
