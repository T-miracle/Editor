## What to build

用户在指定重构工作区使用实际 Rust 和终端插件提供的分组模板、默认参数、原生表单及校验规则。普通模板按适用性展示，Shell 只显示本机可用解释器。新窗口在真实 Windows 中可用，旧配置仅在授权范围内一次性清理，新配置、其他工作区和插件数据保留；发行包、消费者与读者文档完整一致。

这是实际插件和新入口的交付切片，同时承担最后一次整体验收，不单独创建测试、文档或打包工单。

## Acceptance criteria

- [x] C09：实际已启用插件提供的适用模板可选，普通不适用模板置灰并说明原因；安装顺序不静默替换有效提供者。
- [x] C10：终端插件依据本机操作系统和解释器探测，只提供实际可用的 Shell 模板；其他系统及未安装解释器不显示，宿主没有终端或 Shell 专属判断。
- [x] Rust 插件提供实际适用的 Cargo 分组及模板默认值，程序只读、子命令仍可编辑；debug 是模板语义而非宿主虚构固定的 cargo debug 命令。有效配置可经现有真实构建、运行及调试机制使用。
- [x] C28：先识别授权工作区的旧运行配置存储范围，使用隔离副本验证准确的清理和重复执行边界，再进行该工作区一次性切换；不迁移旧配置，不清理主工作区、其他工作区、新配置、安装记录、插件私有数据或全局设置。
- [x] C29：中英文、深浅主题、键盘焦点、原生中文 IME、缩放及长树和长表单滚动完成相关 Windows 交互验收，工具栏与应用、保存、取消按钮不被裁剪。
- [x] C30：更换独立插件身份及布局无需修改宿主；关闭窗口、切换工作区、禁用或退出插件后，面板、事件及校验资源撤销，旧事件不串入新对象。
- [x] 外部下拉保持按钮正下方定位，上部为配置列表或浅灰“暂无配置”，分隔线下方为“编辑配置”；与新配置的红色状态和执行门禁一致。
- [x] 公开 SDK、实际消费者清单版本、能力声明、插件包与发行产物一致；既有终端和其他受影响插件能力保持可用，没有永久旧协议分支。
- [x] 读者文档、维护者验收记录及工单覆盖表同步，逐项读回 C01–C30 的实际证据，明确区分状态测试、GPUI 平台、真实包、真实 Windows 和真实调试器验证；缺少环境不得标记全部完成。
- [x] 使用最终成批回归及原生验收完成交付；验证后没有新变更时复用同一结果，不为同一产物追加无必要的完整检查，且不合并到主分支。

## Testing Decisions

主要负责 C09、C10、C28–C30，汇总全部 C01–C30。真实 Rust、终端包与未知身份提供者复用公开 SDK 构建，并显式运行实际包测试；不同系统的 Shell 筛选夹具不等于各系统真机验证。旧数据清理只在隔离副本验证边界；实际用户数据操作限定既有授权。真实 Windows 操作覆盖输入、焦点、可见布局和关闭清理，最终阶段检查与发行包验收合并组织。
