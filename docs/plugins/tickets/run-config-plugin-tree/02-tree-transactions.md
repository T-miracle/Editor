## What to build

用户在资源管理器式配置树中组织多个插件配置，使用添加、删除、复制、添加文件夹四个图标按钮及拖拽操作。整个窗口保留多条配置和目录树草稿，应用只保存当前配置及必要目录路径，保存提交全部，取消只丢弃未提交内容，使跨配置编辑和撤销结构修改都可预测。

## Acceptance criteria

- [x] C03：四个按钮使用细图标，有悬浮提示和可访问名称，图标、文字及边距一致；没有额外发现配置按钮。
- [x] C11：选中文件夹时新增到其中，选中配置时新增到同级，无选择时新增到根；均追加到所在类别末尾。
- [x] C12、C13：虚拟文件夹支持多层嵌套、拖拽跨父级及根目录移动，拒绝自身或后代循环；文件夹在前，同类顺序手动调整后重开保留，不改变磁盘目录或工作目录。
- [x] C14：复制配置在同级创建内容独立的副本并选中，名称带“副本”含义；文件夹不能复制，取消撤回未保存副本。
- [x] C15：递归删除前展示受影响文件夹和配置数量，确认后只改草稿；取消恢复，保存才提交删除；既有执行会话仍持有自己的启动快照。
- [x] C16：在多个配置间切换，字段及结构草稿均保留，不提前切换外部运行目标。
- [x] C17：应用前校验当前配置，只保存它和维持其位置所需的父级路径；不夹带其他配置修改或无关目录草稿，不改变外部选择。
- [x] C18：应用成功后继续编辑再取消，保留已应用内容，撤回其后的未保存修改和其他草稿，重开与已应用基线一致。
- [x] C19：保存前校验全部配置，获得每条的结果后提交全部配置及树，成功关闭并同步当前配置到外部选择；文件夹或已删除项不能成为可执行的外部引用，写盘失败不误报成功。
- [x] C22：关闭按钮与 Esc 遇到未提交内容时，保存、放弃修改、继续编辑三条路径正确，已应用内容不会被撤回。
- [x] 树、事务和原生操作共同成批验证；涉及相反旧行为的测试按新规格替换，不把“删除立即保存”“错误不可保存”或“项目共享”继续作为有效断言。

## Blocked by

- 01：从插件模板创建并使用配置。模板身份、原生表单及配置持久化闭环是树组织和窗口事务的前提。

## Testing Decisions

主要负责 C03、C11–C19、C22。使用 01 的公开插件及原生窗口入口，一批覆盖多配置切换、新增位置、树循环、排序、复制删除、应用范围、整批保存和三种关闭处置。树与提交不变量补就近测试，持久化失败通过既有存储边界验证；不得用第二份生产配置状态或测试专属 API 绕过真实路径。
