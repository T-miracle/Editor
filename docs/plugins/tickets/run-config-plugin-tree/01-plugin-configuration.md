# 01：从插件模板创建并使用配置

稳定标识：`run-config-plugin-tree-v1/t01`

**Status:** ready-for-agent — 已发布并读回确认，尚未完成实现。

GitHub：[#68](https://github.com/T-miracle/Editor/issues/68)；规格：[#67](https://github.com/T-miracle/Editor/issues/67)。

规格依据：`run-config-plugin-tree-v1`；共同实施和成批测试规则见本批工单索引。

## What to build

用户通过独立插件包获得分组命令模板，打开原生配置窗口，从添加抽屉创建根目录配置，编辑插件提供的原生表单，保存、重开并经既有执行入口使用有效配置。两个身份和布局不同的独立提供者均能完成这一闭环，证明宿主接口可以被任意兼容插件复用。

本切片建立单配置和根目录配置列表的完整可用路径；嵌套目录与多条修改的提交范围由 02 完善。开始时先完成必要的局部职责抽取并明确配置身份、提供者关联、表单与草稿交换及版本化存储边界，保持已有执行行为可验证，不另设预重构工单。

## Acceptance criteria

- [ ] C01：配置窗口沿用插件管理的原生父子窗口机制，左右两栏，不覆盖其他应用或引入 WebView。
- [ ] C02：打开时跟随外部有效配置选择；无有效选择时不自动选中另一条，右栏居中显示“请添加配置”。
- [ ] C04：添加抽屉与左栏等宽、只覆盖树区域，保留工具栏，右侧表单位置不变。
- [ ] C05、C08：独立插件提供分组、图标、名称和默认值；选择后关闭抽屉、创建并选中独立草稿，同一模板可创建多条配置，添加不落盘或执行。
- [ ] C06：两个不同身份、不同原生布局的独立提供者经公开管理器注册，配置值可编辑、保存和重开恢复，宿主无需修改具体插件分支。
- [ ] C07：程序只读，完整参数可编辑；插件预填子命令也可修改，空格、引号、中文和元字符保留结构化参数边界。
- [ ] C27：配置使用稳定身份，按工作区在本机保存，项目目录无新增配置文件，没有“仅本机／项目共享”选择器。
- [ ] 单配置的应用、保存和取消具有可演示路径：调用插件校验后提交，写盘失败保留草稿并报告；未通过或无法校验时从本切片起就禁止配置执行。保存有效配置后可以通过既有会话入口执行，提交本身不启动目标。
- [ ] 公开能力、SDK、宿主和独立消费者同步可用；遵守信任、权限、实例归属及原生面板基础清理规则，不新增专属 API 或开放私有字段给测试。
- [ ] 本切片场景成批验证，真实包及相关应用用例、仓库阶段检查有可读回证据；02、03、04 尚未覆盖的行为不标记完成。

## Blocked by

None — can start immediately after the split is approved and published.

## Testing Decisions

主要负责 C01、C02、C04–C08、C27。共用两个可独立构建的插件提供者和原生窗口驱动，一批验证添加、默认值、原生布局、字面参数、保存重开及受控执行；同时验证最低失败保护。公开 SDK 变化时验证分发及消费者构建，实际 WASM ignored 用例显式运行。复用现有执行、调试和窗口机制，不在本工单重写这些系统。
