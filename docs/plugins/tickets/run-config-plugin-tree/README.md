## 实施边界

- 每张工单同时包含所需公开契约、宿主集成、状态、原生 UI、插件消费者和行为验证，不建立“先做协议、以后再接 UI”的独立水平工单。
- 没有必须单独立项的广域机械重构。必要的局部职责抽取在对应切片开始时先完成，保持既有行为可验证；01 提前确定稳定配置身份、提供者关联及可承载树结构的存储边界，避免 02 再替换整条配置链路。
- 宿主能力向全部插件公开，插件负责模板、布局、默认参数、环境筛选及业务校验。不得按插件身份、语言或程序名加入专属分支，也不得新增测试专用宿主 API。
- 信任、权限、实例归属、关闭回调及失败时禁止执行的保护从 01 开始生效；03 完善故障路径，不是延后补上执行保护。四个切片均通过自身检查后再进入下一张，未完成整批前不作为最终用户发行版交付。
- 生成代码同时补充注释，公开接口说明用途、输入、返回结果、错误及权限；契约变化同步 SDK、消费者和协议文档，实际交付的插件包同步版本与能力声明。

## 成批测试与控制重复消耗

已确认主要测试入口：**独立插件包 → 公开管理器 → 原生配置窗口 → 本机持久化与既有执行入口**。就近状态和协议测试辅助验证树与事务不变量，不能替代这个产品入口。

- 每张工单按完整行为组一起编写实现和相关用例，再通过共同测试入口成批运行；不为每生成一条测试就启动一次完整回归。发现关键未知行为时允许先运行小范围验证，避免把错误假设积累到阶段末。
- 按 **4 个工单交付节点**安排阶段检查。每个节点执行受影响测试及仓库要求的格式检查、非 UI workspace 测试、workspace 编译检查；修改应用时追加相关应用测试和必要的原生交互验收。04 的阶段检查同时承担最终回归，检查后没有新变更或未解决问题时，不再重复追加相同的全量检查。
- 新用例主要围绕可观察行为和失败边界，一个场景可以覆盖多条 User Stories；不要求为 58 条 User Stories 分别生成独立用例，不以累计执行数量作为验收目标。
- 共用公开 SDK 与独立包夹具；输入未变化时复用已构建产物，契约、夹具或消费者变化时才重建。实际 WASM 相关 ignored 测试先构建所需包再显式运行，跳过不计为通过。SDK 和消费者变化时执行相应分发验证。
- 命令由顺序依赖决定，独立的只读检查可以在一次工具调用内收集。完整日志留在本机，只向模型返回退出状态、统计摘要及必要失败片段，避免反复读取成功用例列表和相同长日志。
- 失败后先定位并修复，再重跑受影响的测试；新变更影响更广或存在未解决风险时才扩大验证。成批执行不等于限制失败后的必要重跑，也不削减仓库要求的阶段检查。
- 每张工单记录本次覆盖的 C 编号、实际命令和结果、真实包与 Windows 交互证据以及未验证项。完整验收记录在交付时维护，当前草案不填通过结论。
