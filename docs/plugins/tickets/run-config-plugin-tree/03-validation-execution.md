## What to build

用户可以保存尚未正确配置的内容，配置树和外部选择显示红色名称及原因，构建、运行、调试不能执行这些配置。每次执行前插件重新校验当前快照，环境变化、超时、提供者退出和迟到结果均不会误放行；已有会话的停止和清理持续可用。

本切片完善 01 已有的失败保护，并将校验结果与 02 的单条和整批提交事务、可见状态及所有执行入口连成闭环。

## Acceptance criteria

- [x] C20：应用调用当前配置校验，保存调用全部配置校验；业务失败也保留并提交原值，树及外部选择的名称标红、原因可见，三个配置执行入口不可用。
- [x] C21：提供者缺失、退出、异常、超时及无法校验均有有限结束路径；内容仍能保存，不把无法校验当通过，不无限等待。
- [x] C23：每次构建、运行、调试都先调用插件针对当前快照重新校验；已保存的成功记录不能直接放行，失败时没有配置目标启动、构建或调试副作用。
- [x] C24：配置变为失败或无法校验不禁用已有会话的停止；停止继续遵循会话归属及资源清理规则。
- [x] C25：修改配置、切换工作区及提供者退休后，旧响应不能覆盖新状态或启动目标；取消、超时和退出后不得继续提交过期回调。
- [x] C26：校验成功不授予权限；受限工作区、能力未协商或权限不足仍拒绝执行，表单与配置不能扩大已有授权。
- [x] 业务规则及错误由插件提供，宿主只协调通用状态、协议有效性和授权；参数按结构化边界进入既有受控执行接口，没有具体工具规则或 Shell 拼接。
- [x] 成批故障测试覆盖保存与执行两侧的成功、失败、无法校验和过期结果；更换提供者身份不需要修改宿主，也不通过开放私有保护字段构造故障。

## Blocked by

- 02：配置树组织与多配置保存事务。需要稳定的应用范围、整批保存快照及取消基线，才能验证校验失败和迟到响应不会提交错误对象。

## Testing Decisions

主要负责 C20、C21、C23–C26。共用公开独立包夹具，成批注入校验拒绝、超时、提供者退出、环境变化与迟到响应；观察红色名称、保存原值、执行副作用是否发生，以及已有会话能否停止。有效构建、运行、调试使用既有会话验证入口，故障模拟不报告为真实调试器验收。
