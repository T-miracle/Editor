# 09 — Rust 启动调试与源码断点

状态：ready-for-agent — 已确认并发布，待实施。

GitHub：[本工单 #57](https://github.com/T-miracle/Editor/issues/57)；父设计：[总方案 #48](https://github.com/T-miracle/Editor/issues/48)。

稳定标识：`run-debug-build/09-rust-debug-launch`

## What to build

选择 Rust 配置后点击调试，经构建启动真实调试目标，在源码断点暂停、继续，并由统一面板观察和停止。

本工单属于运行、调试与构建总方案。每个切片在既有公开能力边界内完成模型、接口、提供者、原生 UI 与可观察行为验收；不以只有类型或空界面代替交付。

## Acceptance criteria

- [ ] 实现前定稿调试器、适配协议与传输选择、依赖授权和执行／调试握手，记录依据；不把尚未确认的 DAP 或某调试器当作既有决定。
- [ ] 通过通用公开调试能力接入真实 Rust 调试提供者，复用保存和启动前步骤；调试提供者与执行提供者协作只启动一个目标。
- [ ] 源码可设置、移除断点，统一面板列出断点；真实断点命中定位对应源码并显示暂停状态，继续后恢复运行。
- [ ] 调试面板顶部承接暂停、继续与停止，按连接及目标状态启用；步进和变量功能由 10 扩展，不虚报完整调试已完成。
- [ ] 没有调试能力时按钮禁用且给出原因，不以普通运行替代；调试器启动或连接失败清理已创建资源。
- [ ] 停机、重新运行和离开确认覆盖调试器及受管目标进程树；接口预留资源所有权区分，不开放附加入口。
- [ ] 以真实 Rust 构建产物验收断点、暂停／继续、退出和失败清理；宿主没有 Rust、服务器名称或插件 ID 专属分支。
