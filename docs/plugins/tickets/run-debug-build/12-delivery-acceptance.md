# 12 — 独立插件接入与整体验收交付

状态：ready-for-agent — 已确认并发布，待实施。

GitHub：[本工单 #60](https://github.com/T-miracle/Editor/issues/60)；父设计：[总方案 #48](https://github.com/T-miracle/Editor/issues/48)。

稳定标识：`run-debug-build/12-delivery-acceptance`

## What to build

外部开发者仅凭公开 SDK 接入执行或调试提供者，用户安装后在完整 B1 流程中配置、运行、调试并安全退出。

本工单属于运行、调试与构建总方案。每个切片在既有公开能力边界内完成模型、接口、提供者、原生 UI 与可观察行为验收；不以只有类型或空界面代替交付。

## Acceptance criteria

- [ ] 用宿主导出的 SDK 独立构建消费者与替代提供者并打包安装，实际从 B1 与顶栏执行；不依赖仓库内部 crate、SDK 源码副本或宿主白名单。
- [ ] 公开能力文档和示例覆盖发现、程序／Shell、构建、会话观察、停止、调试与资源生命周期；SDK 与受影响插件包版本匹配。
- [ ] 以两个隔离项目验证共享配置与本机覆盖，再执行真实 Rust 完整调试、并行会话和生命周期流程，逐项核对 R01–R20。
- [ ] 原生验收 B1 四标签、统一下拉、断点定位、窗口离开、受限工作区、深浅主题、中英文、键盘、IME、滚动与缩放。
- [ ] 各前序工单已自行具备行为测试；本工单增加组合回归和交付演示，不替前序补做首次权限或正常路径测试。
- [ ] 完成针对性、workspace、应用与 SDK 分发检查，构建实际 WASM 夹具并显式执行所需 ignored 测试，记录失败与环境限制。
- [ ] 读者使用说明与插件协议正文按站点规则只写入读者文档工作面；维护者验收与议题映射留在内部文档，不复制读者正文。
- [ ] 验收通过后才标记整批完成；不自动发布版本，不宣称未经实测平台已通过。
