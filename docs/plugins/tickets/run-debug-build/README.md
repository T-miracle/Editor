## 依赖与前沿

仅列直接阻塞项，不重复传递依赖。获批后的初始前沿为 01；01 完成后 02 与 04 就绪，02 完成后 03 就绪。其余按表中的全部阻塞项判断。就绪不代表授权并行委派；按当前协作约定逐张处理。

没有证据要求全仓广域预重构，不单列“先做基础层／API／UI”的水平工单。最小必要的模块搬迁在所属切片开始时完成并验证，随后交付可运行行为。01 已落实基础终止、权限与资源归属，02 增加正常退出与离开确认，11 扩展管理变更及事务故障联动，不能把安全正确性全部延后。

09 只承诺真实启动调试与断点闭环；10 扩展完整单步、栈帧、变量及多会话交互。两张各有可演示产物，12 验证整条交付流程而非首次测试。

## 决策归属

- 01：最小配置存储与版本、公共执行会话身份和状态、错误与资源契约。
- 02：正常退出请求机制、超时默认值和立即终止行为。
- 04：显式 Shell 与环境传递、参数编辑及本机覆盖契约。
- 05：构建与启动步骤表达，以及此前未确认的单独构建保存策略。
- 06：共享配置文件名、格式、变量集合和覆盖迁移。
- 07：发现贡献、候选去重和目标失效协议。
- 08：单配置提供者选择、公开插件消费者 API 与 SDK 文档。
- 09：调试器与适配协议、授权依赖、执行／调试提供者握手。
- 10：暂停上下文和变量／栈帧引用失效。

这些细节在对应切片进入实现前落实；不能把尚未做出的产品决策冒充用户已确认。若选择改变已确认行为，需要说明具体差异。
