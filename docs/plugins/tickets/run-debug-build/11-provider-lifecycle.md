# 11 — 插件变更确认与会话故障回收

状态：ready-for-agent — 已确认并发布，待实施。

GitHub：[本工单 #59](https://github.com/T-miracle/Editor/issues/59)；父设计：[总方案 #48](https://github.com/T-miracle/Editor/issues/48)。

稳定标识：`run-debug-build/11-provider-lifecycle`

## What to build

停用、卸载或更新执行／调试插件时列出受影响会话，用户决定是否停止；插件崩溃后可见失败且无命令重放。

本工单属于运行、调试与构建总方案。每个切片在既有公开能力边界内完成模型、接口、提供者、原生 UI 与可观察行为验收；不以只有类型或空界面代替交付。

## Acceptance criteria

- [ ] 插件管理操作识别执行和调试提供者受影响会话；确认停止后才进入破坏性变更，取消保持会话与插件。
- [ ] 正常停止、立即终止及超时清理沿公共会话入口，分别验证普通运行、构建准备和断点暂停状态。
- [ ] 更新准备失败保留旧实例；切换或激活失败继续遵循旧版本与受管数据恢复，不借恢复重新执行用户命令。
- [ ] 提供者崩溃或来源实例撤销使相关会话明确失败，清理拥有的目标、调试器、订阅与展示；不影响无关会话。
- [ ] 旧提供者引用、停止通知或事件不能复活会话，也不能对新实例发起操作。
- [ ] 沿真实插件管理流程注入故障并核对实际进程和原生提示；不用单独的插件专属测试接口。
- [ ] 此工单补全管理确认与事务交互；前序工单的基础权限、异常清理与不重放保障不能推迟到此工单才实现。
