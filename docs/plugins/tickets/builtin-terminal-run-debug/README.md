## 边界与阶段可交付性

每张工单都包含自身的实现、公开接口适配、可见界面、回归测试和相关文档；不按核心、UI、协议、测试各拆一单。04 的主要交付是旧用户真实升级和发行切换，不是把前三张欠缺的验证留到最后。

当前没有证据表明必须采用只能在最后变绿的广域机械重构。按逐单可编译、可验证组织：先整理可复用的通用资源边界，再接通行为。若实施发现无法独立保持绿色的具体共享契约，应记录受影响消费者和原因，再调整批次，不默认为所有工单最后才验收。

中间切片在隔离数据根验证，不提前向现有用户做不完整数据切换。旧终端源码和发行引用仅在仍有未迁移消费者时暂存，既有协议消费者继续可验证；04 在迁移完成后统一收缩删除。不新增永久旧协议兼容链，也不允许在同一用户会话展示新旧两个终端入口。前三张通过不等于已完成旧用户发行升级。

信任、权限、资源归属和错误清理从首个可执行切片就必须有效；N16 由 02 汇总验收不代表 01 可以不做权限保护。03 复用并验证关闭行为在真实调试目标上的结果，不重写 02 的普通运行用例。

## 主责覆盖与少重复测试

主要测试入口沿用总方案提案：**编辑器实际操作 → 内置终端及通用服务 → 真实进程与调试器 → 可见结果和持久状态**。在隔离工作区验证，语言和调试器仍使用实际插件包；不安装终端包、不新增测试专用宿主 API。该入口与本次拆分一起提交用户确认。

26 项 N 编号各有且仅有一个主责工单。主责负责最终记录该项证据，不阻止其他工单验证自己触及的交集：例如 01 验证普通 Shell 关闭，02 验证任务关闭，03 验证调试进程清理，04 验证重启不重放；这些是不同风险，不算重复测试。

| 阶段 | 重点测试批次 | 可复用与补测边界 |
| --- | --- | --- |
| 01 | Alacritty + 真实 Shell + 本地控件交互，涵盖 TUI、宽字符、主题、IME、resize | 建立共用隔离窗口和 PTY 夹具；不构建即将退役的终端包作为新功能前提 |
| 02 | 准备/构建/运行组合、公开调用与关闭/复用状态，配合少量权限和故障注入 | 复用 01 的窗口、进程和绘制夹具；不为每一种菜单重复完整 Shell 交互清单 |
| 03 | 真实调试目标的输入、断点和检查组合；初始化失败与进程树清理 | 调试器与受影响 SDK 消费者按输入变化重建；只补调试特有生命周期边界，不再复制普通运行全套用例 |
| 04 | 真实旧数据导入、失败重试、重启和升级产物；一个混合 Shell/构建/运行/调试场景 | 升级改动触及的恢复、注册与发行链必须重测；其他未受影响证据核对后复用，不把 26 项原样再做一遍 |

### 每张工单的质量门禁

1. 开发中先用最小相关测试验证高风险假设，行为实现成组后集中执行针对性回归；不在每次小改动后启动全 workspace 或整套真实调试验收。
2. 每个交付节点都执行仓库要求的 `cargo fmt --check`、`cargo test --workspace --exclude editor-app`、`cargo check --workspace`，以及相关应用测试和必要的原生交互验证。这是四个完整交付节点的基础门禁，不以节省测试为由跳过。
3. 04 的交付检查同时承担最终整体验收；通过后若没有新的代码、契约、产物变化或未解决问题，不再安排第五轮相同全量检查。
4. 已构建包与测试证据只有在代码/依赖、SDK、夹具、配置和环境输入未变，且受影响分析表明该行为未被后续改动触及时才能复用。记录提交或工作树指纹、产物版本/哈希、命令、结果和覆盖编号，不能只写“之前通过”。
5. 真实包相关 ignored 测试先准备当前夹具再显式执行；跳过不计通过。公开契约变化时同步重建受影响消费者并验证 SDK 分发，不给每条普通 UI 测试重复构建所有插件。
6. 失败后修复并重跑受影响测试；影响范围扩大则相应扩大回归。不得为了满足固定测试次数而复用失效证据。后续修改影响前单场景时，在当前工单补测并记录，不把问题推回已经交付的工单。
7. 每单交付记录区分状态/协议、GPUI 自动化、真实包、真实 Windows 交互和其他平台验证；说明未验证部分，不将模拟输入或编译通过当作交互验收。

## 发布计划

用户批准粒度、依赖和主要验收入口后，按稳定标识检查重复，先发布此前授权的规格，再按顺序发布四张工单，共 **1 个规格议题 + 4 个实施工单**。工单引用真实父议题，使用 `ready-for-agent`，建立三条 GitHub 原生阻塞边，并读回正文、标签、关系及真实数据库 ID 后登记发布记录。

若原生关系工具不可用，按仓库流程使用已认证 API；仅在原生能力确实不可用时才回退正文链接并记录限制。不修改或关闭父议题，不因发布而自动开始实现、提交或推送。
