# 03：交互式调试与统一检查界面

稳定标识：`builtin-terminal-run-debug/t03`

**Status:** completed — 已完成实际调试输入、检查界面、公开能力与清理验收；记录见 [03 验收](../../verification/builtin-terminal-03-2026-10-09.md)，对应 [#90](https://github.com/T-miracle/Nanobug/issues/90)。

规格标识：`builtin-terminal-run-debug`；主责验收 N03、N12–N15。

## What to build

用户从现有调试入口启动一个需要输入的真实程序，在内置终端中输入并查看输出，在同一底部面板使用断点、继续、暂停、单步、变量和调用栈。调试输出和宿主检查区不再额外占据面板；普通 Shell 和运行任务同时存在时不受干扰。

通过公开通用能力连接调试插件与原生 PTY，调试插件继续处理具体协议和适配器。复用 02 的任务身份、Tab 复用及确认停止机制，不新增第二套调试任务管理。

## Acceptance criteria

- [x] N03：Shell、构建、运行和调试混合使用时只有统一底部终端面板，不再出现旧调试输出面板或额外宿主检查块，文件 Tab 不承载这些工具内容。
- [x] N12：选中调试 Tab 在同一面板内部显示控制、变量、调用栈和断点；切回 Shell 或运行 Tab 时焦点及输入目标正确，已有源码导航与暂停焦点策略保留。
- [x] N13：实际 Rust 调试程序只启动一个目标实例，在 PTY 中等待、接收用户输入并输出结果；输入后仍能命中断点和检查状态，不以普通运行副本或文本控件模拟调试交互。
- [x] 调试插件继续拥有启动编排及具体 DAP/调试器映射；宿主只处理通用终端和受控资源，目标输入输出与调试协议通道隔离，不加入 Rust 或 CodeLLDB 专属业务分支。
- [x] N14：真实断点、Pause/Continue、步入/步过/步出、调用栈和变量可用；两个会话及不同暂停代次的迟到检查结果不串入当前视图。
- [x] N15：初始化失败、连接超时、启动中取消、调试器退出和插件退休均有明确错误及受管进程树/PTY/订阅清理，不静默降级为普通运行。
- [x] 02 的关闭确认、取消、结束后关闭、面板隐藏、重新运行、窗口退出与工作区切换在真实调试会话上成立；未结束目标不得因 UI 关闭失去控制入口。
- [x] 通用能力通过版本协商和来源权限校验；独立调试消费者可接入，不使用测试专用协议或按提供者身份跳过检查。
- [x] 更新受影响的调试器包版本、公开 SDK、能力声明、消费者及文档，现有语言构建规则和配置表单保留；不新增表达式 REPL、附加或远程调试。
- [x] 完成真实调试 stdin 与原生检查操作验收、失败清理回归及本单阶段门禁，明确实际平台和工具链限制，不将现有普通运行输入测试算作调试输入通过。

## Testing Decisions

扩展已有真实 Rust/PDB 调试夹具，以一次有意义的输入、断点、检查和步进组合贯通真实按钮与绘制命中区域，再用两个独立会话验证归属。增加调试握手失败和取消的有界测试，确认目标仅启动一次并最终回收相关进程。

复用 02 的任务生命周期用例，仅增加调试资源特有的断言和真实会话场景，不复制普通运行全部边界用例。SDK、适配器和消费者输入未变可复用已构建产物；发生契约变更必须重建相关包并显式执行实际包测试。主题及普通 Shell 交互仅在此次布局或焦点改变触及时扩大回归。执行本批阶段门禁与证据记录。
