# 04：旧用户迁移与内置发行交付

稳定标识：`builtin-terminal-run-debug/t04`

**Status:** planned — 已批准并发布为 [#91](https://github.com/T-miracle/Nanobug/issues/91)，等待 03 完成。

规格标识：`builtin-terminal-run-debug`；主责验收 N18–N21，汇总全批有效证据。

## What to build

已有终端插件的用户升级后，直接使用内置终端，原设置、Tab、Shell、工作目录、历史输出、布局和运行配置继续可用，旧数据有备份且旧插件不会重复加载。新发行的编辑器无需终端包即可使用 Shell、构建、运行和调试。

在前三张已验证行为的基础上完成真实旧数据导入、失败恢复与发行收缩。该工单交付一条完整升级路径，同时完成最终组合验收，不用于补做前三张本应完成的功能或基础测试。

## Acceptance criteria

- [ ] N18：通过实际运行时的工作区范围解析旧终端安装、设置和快照，备份后迁移 Tab 名称/顺序、Shell 类型、cwd、历史、主题和布局；既有 Shell 配置来源及执行引用迁移后可用。
- [ ] N19：迁移写入与完成标记有一致性保护；重复启动不重复导入，不覆盖新状态；中途失败和损坏样本保留原数据与可诊断结果，不静默清空。
- [ ] N20：不同工作区互不串用；普通 Shell 仅在信任条件允许时重建新进程，旧运行/调试输出恢复为非运行状态，不自动重放命令或目标程序。
- [ ] N21：旧格式转换保留可见内容与顺序，恢复不注入提示或额外换行；恢复后连续改变宽高、长行与历史滚动不产生重复提示和额外空白，历史容量约束保持。
- [ ] 成功迁移后旧终端的安装加载、贡献、提供者引用和独立构建/发行入口退役，终端功能目录及不再需要的专用 WASM/旧核心链收缩；不删除其他插件所需通用能力，也不删除用户备份。
- [ ] 有限迁移对旧身份和格式的识别不会进入长期业务分发；不新增永久旧协议兼容链、隐藏终端插件或重复可见入口。
- [ ] 实际升级产物中无终端包时，用户可打开 Shell、运行和构建项目、启动交互调试；存在旧安装记录时只出现一个终端，运行配置和公开消费者仍有效。
- [ ] 新存储及发行变化触及的注册、持久化、权限、恢复与配置启动路径完成必要补测；检查其他插件数据和已有 MeEditor 标识未被误改。
- [ ] 完成一个包含恢复、Shell、构建、运行、调试输入与退出的实际组合场景；对 N01–N26 逐项登记本单新证据或仍有效的前单证据，不机械重跑全部场景也不借引用跳过受影响项。
- [ ] 维护者与读者文档、直接构建/打包入口、SDK 和实际插件消费者与最终实现一致，清除仍要求构建终端包的现行测试前提和发行说明；历史验收保留原时点记录。
- [ ] 本单交付门禁同时作为最终检查，实际 Windows 升级和交互通过才宣称相应功能完成；其他平台按真实结果注明限制，缺少工具链不自动安装。

## Testing Decisions

在隔离旧数据副本中经应用启动与恢复入口验证迁移成功、重复执行、失败中断及修复重试，不操作用户真实历史作为测试夹具。旧核心格式转换测试覆盖历史顺序、显示状态和容量边界；真实恢复后 resize 和继续输入确认画面与光标，而非仅断言数据反序列化成功。

用最终产物同时验证全新安装与旧记录升级，运行一次有代表性的混合会话场景。检查前三张证据的代码/依赖、SDK、夹具、配置、环境输入及行为影响；不受本单改动影响的部分引用证据，受影响部分补测。执行一次本单仓库基础门禁及相关应用、真实包和 Windows 验收；通过且无新变化后不再附加相同全量检查。发布软件版本或自动开始后续工作不在本单授权内。
