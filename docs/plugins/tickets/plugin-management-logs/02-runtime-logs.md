# 02 — 查看完整日志并识别未读异常

**Status:** completed — 已实现并通过 Windows 行为验收，2026-10-04。
GitHub：[#24](https://github.com/T-miracle/Editor/issues/24)；父方案：[#22](https://github.com/T-miracle/Editor/issues/22)。
规格：[插件管理与运行日志改造](../../specs/plugin-management-logs.md)。

## What to build

插件输出、语言服务启动/退出/重试与宿主诊断经真实运行链路进入该插件日志页。用户能读懂时间和来源，通过 Tab 图标识别未读异常，查看后清除提醒而保留日志。本切片同时交付记录状态、实际来源接入和原生呈现。

## Acceptance criteria

- [x] 日志有稳定身份、插件归属、时间、级别、来源与消息，终端命令输出不进入日志。
- [x] 每插件有界保存本次进程记录；关闭弹窗和切换插件不清空，编辑器重启清空，明确并验证条数上限。
- [x] Tab 图标反映最高未读级别：红色错误优先于黄色警告，普通记录无提醒图标。
- [x] 进入日志页标记进入时对应插件记录已读，条目级别与颜色保留，不影响其他插件或并发新记录。
- [x] 正常过期 UI 回调继续被拒绝，但不作为插件故障进入红色提醒；真实错误仍可诊断。
- [x] 不新增筛选、清空按钮或自动跟随；日志页长内容可读且按既定区域滚动。

## Testing Decisions

覆盖 U04–U06、U10–U12 中日志与 Tab 部分。由实际插件包及受控服务夹具产生记录，再从原生界面确认可见消息和图标变化。补充跨插件、淘汰边界、并发新日志及迟到 UI 回调回归；执行相关真实组件用例及仓库阶段检查。

实际命令、结果和平台边界见[运行日志验证](../../verification/plugin-runtime-logs-verification.md)。每插件保留 512 条、每条最多 8192 个 Unicode 标量；SDK 夹具与真实原生 LSP 验收均已显式执行。
