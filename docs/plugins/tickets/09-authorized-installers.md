## What to build

确实需要安装程序的服务在安装弹窗中说明用途，用户授权后完成私有安装；拒绝不执行脚本，缺少大型 SDK 时由用户主动选择。

在声明式依赖管理之外补齐受控原生安装步骤，不建立特定语言服务器的安装分支。

## Acceptance criteria

- [x] 安装方案明确程序、参数、目标与用途，执行权限与下载解包、启动服务及任意命令权限分别表达。
- [x] 未获授权不执行；新增安装权限更新需要重新确认，拒绝后旧版本继续使用。
- [x] 默认目标为私有目录，解释原生程序仍具有实际 OS 权限，不把目录隔离描述为系统沙箱。
- [x] 大型编译器及项目 SDK 缺失时仅提示；用户主动选择和授权后才执行相应方案。
- [x] 失败、取消和重试有确定结果，清理受管临时内容，不声称撤销外部副作用。
- [x] 成功后的服务沿既有 LSP 流程启动，失败安装不能发布半成品依赖为可用缓存。

## Implementation guardrails

- 使用已确认的现有包管理器与编辑器集成测试边界，不新增插件专属测试入口。
- 只改变本工单范围，保留工作区已有改动；新增代码同时补充意图和不变量注释。
- 复用既有模块；必要的预重构先保持行为不变并通过相关回归，再加入新行为。
- 测试使用隔离目录与夹具，不操作用户真实插件安装数据；不提交 Git、不发布中间版本。
- 流程与契约细化若改变已确认产品行为，应先评审；不能以实现方便引入插件专属分支。
