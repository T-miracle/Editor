## 用户补充：Image 插件（2026-10-05）

工单 01 改为将现有 SVG 插件升级为通用图片插件，用户可见名称为 `Image`。SVG 继续支持源码编辑和未保存内容预览；首期复用现有 SVG、PNG、JPEG、GIF、WebP 能力，其他声明图片格式只读预览。

默认按图片自身宽高显示，小图不自动放大；任一方向超过实际预览内容区域时等比缩小至完整可见。自动适配状态下切换图片、调整区域或修改 SVG 尺寸都重新计算，区域扩大后最多恢复原尺寸。原 SVG 默认最长边 240px 的规则由此替代；已有 SVG 手动缩放仍保留。

这项用户补充将 #61 的 PNG 非文本验证场景扩展为实际 `Image` 插件交付，SVG 编辑能力在 01 即需回归；04 负责 `Image` 与其他插件的通用布局、底栏、配色和偏好迁移，不重复改名或增加图片格式。图片修改、编码转换、导出及新增动画播放功能不在本批新增范围内。父议题保持原状，后续发布工单正文明确引用这项补充。

## 拆分原则

- 保留 5 个粗工单。文件身份、协议、运行时、SDK、宿主绘制和对应测试按用户行为一起完成，不拆为只有类型、只有界面或只有测试的小工单。
- 工单 01 通过实际 `Image` 包、02–03 通过真实或最小有效插件包进入公开 Package／Manager，再在原生界面演示行为；工单 04 将成熟布局和工具能力一次用于既有插件。工单 05 是跨模块迁移的最终收缩与集成验收，不重复建立另一套测试架构。
- 已识别的必要预重构集中在工单 01 开头，保持现有行为并验证后再增加功能，不单独建重构工单。其后扩展已建立的接口，避免再做无关结构调整。
- 各单只引用自己负责的用户故事和验收场景，不复制总方案全部正文。权限、唯一文本状态、原生 UI 基座、revision 和资源归属等共同不变量始终有效。

## 验证安排与重复开销

1. **工单内部**：每个相关行为变化做针对性测试；按失败、代码变更或新的风险扩大范围。同一代码和包产物已经通过的检查不因总结、换上下文或填写状态而重复执行。
2. **粗工单交付**：一次执行该单的公开包纵向验证、受影响 GPUI／原生交互，以及仓库要求的 `cargo fmt --check`、`cargo test --workspace --exclude editor-app`、`cargo check --workspace`。应用测试按影响范围过滤，不默认运行全部应用测试。
3. **SDK 与实际包**：影响 SDK 契约或分发时，在该单交付边界完成宿主构建及 SDK 分发验证；真实 WASM 按夹具要求构建，显式运行对应 ignored 测试。复用与当前内容一致的构建缓存，不把过期产物当新包。
4. **工单 05**：统一执行 U01–U20 与 Image 补充 I01–I03、Markdown／Image／终端／其他受影响插件回归、独立插件和 SDK 分发、故障与原生交互验收，并检查最终代码与包版本组合。此前已通过且未受收缩影响的场景可引用有效证据；涉及跨功能组合、最终产物或后续改动的场景重新执行。
5. **证据**：每单一份阶段记录，注明实际命令、源码与包版本、结果、失败原因和未验证项。摘要记录测试目标与可接续状态，不复制完整输出。功能未满足、ignored 未执行或工具缺失均不能标为通过。

[仓库约定](../../../../AGENT.md)及本次用户提供的 AGENTS.md 要求每个实现阶段交付前三项基础检查，[总方案](../../specs/plugin-ui-decoupling.md)也沿用这一要求。采用“一粗工单一交付检查”，不更改验证门禁；完整跨插件集成集中在 05，减少小步骤交付和无变化的重复验证。

## 预重构与广域迁移

必要的文件 Tab／文本会话访问集中整理、目标身份校验接缝及现有中心绘制入口搬迁，在 01 开头先保持行为完成并做现有文本回归；实际将文本会话改为可选仍属于 01 的新行为，不冒充纯重构。

优先以当前协议上的能力扩展让已有功能保持可验证，再由 04 迁移实际消费者、05 收缩临时内部结构。不得增加历史协议运行适配或永久双业务实现。若定稿契约证明某项共享改动无法逐单保持可编译／可验证，明确将相关改动留在同一集成分支，由 05 承接最终可交付基线；不能把无法验证的单据标为独立已交付，也不能静默发布中间不兼容包。

技术细化不得改变 #61 的文件 Tab 用途、同类文件一起切换、可选原生编辑器、单一整体布局归属及文本／非文本恢复区别。
