# 运行、调试与构建 验收记录

本文件记录 `docs/plugins/specs/run-debug-build.md`（父设计 [#48](https://github.com/T-miracle/Editor/issues/48)）各工单的实际验收证据与实现期确认的决策。规划文档位于主工作区，实现与提交在当前任务分支 `codex/run-debug-build`。

## 实现期决策

### D1 单独构建的保存策略（工单 05 要求先记录）

**结论**：单独构建与运行使用同一份**已保存**的配置，两者都不引入隐式保存。

- 点击构建或运行前，按既有自动保存流程确认脏文档（`save_dirty_documents`），失败或取消则不启动任何步骤。
- 未保存的配置草稿不产生任何进程，也不进入启动前步骤序列。
- **明确不采用**「为单独构建临时落盘一份草稿」的做法：它会绕过用户对保存的确认，属于此前未确认的产品行为，且与运行的保存规则不一致。

**影响**：构建与运行的行为一致，用户可以预测「屏幕上看到的配置」与「实际执行的配置」何时相同；代价是未保存的编辑必须先保存才能构建。

### D2 执行契约的可观察退出（工单 05 的技术前提）

构建步骤以「程序结束」为完成条件。宿主原先只能得知「程序已启动」，因此把「可观察退出」作为执行契约 **1.3** 的 `status` 方法补入，而不是用延时或日志猜测。宿主要求自己声明的每个方法，因此无法报告退出的提供者属于**不兼容**，而不是「看起来可用但永远不返回」。

### D3 步骤引用而非复制（工单 05）

启动前步骤通过 `@配置名` 引用另一配置的构建动作，存的是**配置标识**而非命令副本。修改被引用配置的构建定义后，引用即刻生效，不会出现两份会漂移的命令。

## 逐工单证据

真实 WASM 包测试以 `-- --ignored` 显式执行；被跳过的测试不计为通过。

### 01 手动配置运行真实程序（[#49](https://github.com/T-miracle/Editor/issues/49)）

- 宿主会话：`cargo test -p plugin-runtime --test host_execution -- --ignored` —— 启动一次并定位既有会话、缺失提供者被报告而不是被替换。
- 垂直验收：`cargo test -p editor-app --bin editor-app extensions::native_run_tests -- --ignored` —— 真实终端包内启动真实程序并观察到其输出。
- 就近回归：`cargo test -p editor-app --bin editor-app run::`。

### 02 正常停止、重新运行与离开确认（[#50](https://github.com/T-miracle/Editor/issues/50)）

- 停止经提供者会话完成（`host_controls_stop_the_program_a_session_owns`），宿主不借用提供者私有进程句柄，确认收到不等于程序已退出。
- 离开确认：有活动会话时窗口不关闭，确认后逐个停止会话再离开；取消留在原处。

### 03 统一下拉管理并行会话与输出（[#51](https://github.com/T-miracle/Editor/issues/51)）

- 两个配置并行运行互不干扰；同一配置重复启动只定位既有会话。
- 隐藏输出页签不停止程序：进程数不变、会话仍可停止、重新选中可恢复输出。

### 04 Shell 脚本与本机环境配置（[#52](https://github.com/T-miracle/Editor/issues/52)）

- 程序模式参数逐项编辑，含空格/中文的参数原样传递；Shell 模式显式选择解释器，脚本文本作为单个末尾参数，实测解释器求值成功。
- 环境变量：执行契约 1.2 的有界条目沿「真实插件包 → 公开管理器 → 受控进程」贯通，验收证明值确实到达子进程（子进程打印该值进入终端绘制）。
- 本机工具路径：成为**该次启动**的前置 `PATH`，用户自己的 `PATH` 保留在后，进入子进程的 `PATH` 只有一个。验收过程中发现 4 KiB 的环境值上限装不下真实 `PATH`，已改为 32 KiB 并同步契约 schema。
- 受限工作区不启动程序；配置不能提权、不能覆盖用户语言/主题/信任状态。

### 05 独立构建与顺序启动前步骤（[#53](https://github.com/T-miracle/Editor/issues/53)）

- 构建操作与启动前步骤分别存储，可分别编辑；后者可用 `@配置名` 引用另一配置的构建（决策 D3）。
- 构建页每个预置动作一行，带该行的上移、下移、删除与末尾的添加控件；不能执行的控制禁用而非静默无效。添加产生的是**模板行**（写作注释），既不消失也不会让配置在写完之前无效。
- 「构建」只执行本配置的构建操作：不跑启动前步骤、不启动程序；无构建操作时按钮禁用并给出原因，构建进行中再次点击不会并行构建同一份代码。
- 运行先顺序准备，步骤以**提供者观察到的进程结束**为继续条件（契约 1.3，决策 D2）；失败、被终止、结束状态无法确认、用户停止，都阻断后续全部步骤并报出是哪一步。
- 准备期间停止：先停当前步骤**自己拥有的**那个会话，并在其结束前保持序列仍被占用，因此窗口不会在准备程序还在终止时关闭。
- 步骤引用不复制命令：改被引用配置的构建定义后，下次启动执行的是新定义，而引用方存的仍是配置标识。

**真实包验收**（`extensions::native_build_tests -- --ignored`，5 项）：两步按序执行后才是程序；一处失败阻断后续与程序；单独构建只跑构建动作；准备中停止不产生启动副作用；引用跟随被引用构建的当前定义。

就近回归：`cargo test -p editor-app --bin editor-app run::`（44 项，含构建页行级编辑的原生检查）。

### 06 共享配置与本机覆盖（[#54](https://github.com/T-miracle/Editor/issues/54)）

- 共享文件 `.editor/runs.json`（格式版本 1）只承载可移植一半：名称、目标与字面参数、**项目相对**目录（项目根写作 `${workspace}` 记号）、构建与启动前步骤。环境变量值、变量名、个人工具路径、项目外绝对路径均不写入——有断言直接在文件字节里检索这些内容。
- 工作区打开时读取本机记录并与项目共享合并；项目条目的可移植一半来自项目，本机环境与工具目录按标识应用，工具目录仍作为该次启动的前置 `PATH`。
- 两个隔离工作区加载同一共享条目时，`${workspace}` 各自解析到自己的项目根；另一台机器的本机值读不到。
- 保存去向在对话框底部二选一（默认仅本机）：仅本机不创建项目文件；选择项目共享写入项目文件。取消不写任何东西；取消共享与删除共享配置都会从项目文件移除该条目，不会在下次加载时复活。
- 手工修改共享文件按**同一契约**校验：违反规则时在工作区打开时就报出原因，且不替换本机已有配置。
- 稳定身份与活动会话隔离：启动被接受时计划即固定，运行中的会话继续使用启动快照；保存或文件变化只作用于后续执行。

**就近回归**：`cargo test -p editor-app --bin editor-app run::`（含加载共享条目后准备出的请求：顺序来自项目文件、参数保持字面项、`${workspace}` 解析到本工作区、本机环境与工具目录生效）。

### 07 Rust 目标发现、保存与修复（[#55](https://github.com/T-miracle/Editor/issues/55)）

- 发现是**声明式贡献**：插件在自己的贡献文件里列出发现声明，宿主读取并应用。宿主词汇刻意很小（节、键、文件模式、字段默认值），不包含任何语言或构建系统专属分支。
- 每个候选带稳定身份（提供者 id + 目标在文件中的名称）、来源、目标类型与字段；宿主**要求提供者指明程序字段**，不会从显示标签臆造可执行文件——目标因此不会以「找不到文件」在启动时失败。
- 候选必须**经用户确认**才成为配置；发现本身不运行目标、不写入任何配置、不把所有候选塞进菜单。确认后立即打开配置弹窗以便修改。
- 重发现不覆盖用户修改、不重复保存：配置记住它来自哪个目标，**只更正程序**，名称、参数、环境、工具目录、步骤与共享选择原样保留。
- 目标改名或消失时配置被标记为**失效**（在选择处可见，并有修复入口），但**不被删除**；在发现运行之前不标记任何东西。
- 提供者可以提供字段**默认值**，用于声明「这类目标通过哪条工具链运行」，而不要求每个项目重复书写。
- 包管理器自己的子命令属于**启动前步骤**，不属于程序字段：程序字段保留「将来调试器要附加的程序」这一含义。

**真实包验收**（`extensions::native_discovery_tests -- --ignored`，1 项）：临时工作区里的**真实 Cargo 项目**经装好的 Rust 插件自己的声明被发现、确认成配置并运行；构建产出 `target/debug/<package>.exe`，程序会话在该项目目录中运行，计划为 构建 → 运行 → 程序。**未安装工具链时该用例跳过而非失败**，并打印跳过原因。

**就近回归**：`contributions`（真实 `Cargo.toml` 产出目标、身份不一致与缺失声明文件被报出）、`plugin-schema` 16 项、`editor-core` 21 项、`run::` 46 项。

### 08 执行提供者选择与调用（[#56](https://github.com/T-miracle/Editor/issues/56)）

- 调试页列出每个声明了执行契约的提供者、显示当前生效者，并允许配置「跟随默认」或指定一个。**装了但不能用的提供者仍被列出并给出原因**（未启用、不兼容、运行出错、契约不完整），且**不可选**。
- 选择记在**配置**上（共享条目只在本地记录保留该关联），因此切换作用域默认值不会静默改掉明确指定过提供者的配置；「跟随默认」是**移除**请求而非挑一个。选择同时应用到作用域，使所有启动路径一致，**只影响此后的启动**。
- 选择由运行时自己的版本化存储保存（`service-providers.json`），本工单没有新建第二份记录。
- **会话绑定启动它的提供者实例**：切换选择不会移动正在运行的会话；**只有启动它的提供者处于选中状态时该会话才可停止**，提供者永远不会被要求结束不是它启动的程序。
- 契约形状**精确匹配**（含 `env` 参数与 32768 字节上限）：收不到宿主所发内容的提供者服务不了本宿主。

**真实包验收**：
- `host_execution -- --ignored`（6 项）：已安装提供者被列出且被选中、禁用后仍带原因列出；**两个独立提供者服务同一消费者**（真实终端包与另一个不同 ID 的独立打包提供者，各自启动、定位、呈现、停止；切换不移动活动会话；只有自己的提供者能停自己的会话）；**启动请求的环境变量真的到达程序**（程序自己打印出的值，而非宿主断言）。
- `plugin_services -- --ignored`（4 项）：唯一/被选中的提供者互换、旧引用失效、缺失或不兼容的服务不激活必需消费者、调用保持来源且不能借用提供者权限或重入、委派资源与异步续体遵循原来源生命周期。
- `scoped_instances`（5 项）：资源句柄拒绝外来与已退休的所有者并释放全部视图；项目禁用保留其他工作区句柄；受限工作区不能授予访问。

**已知未验证**：宿主会话表的容量上限（`MAX_HOST_EXECUTIONS`）在**全部会话都处于活动状态**时不会驱逐任何条目——驱逐只针对已结束项，因为静默丢弃一个正在运行的程序更糟。本轮没有构造出「会话表达到上限」的可观察用例：真实包测试每个用例只启动少数程序，而构造 64 个并发会话的成本与收益不成比例。因此该上限的**行为**（超出时先驱逐已结束项）只有实现与注释佐证，没有测试证据。

## 未覆盖与限制

- 被跳过的 `#[ignore]` 真实包测试需要先构建夹具（终端包与 capability-example）并已被显式执行；未执行的跳过项不计入通过。
- 原生交互验收（深浅主题、缩放、滚动、弹窗受限尺寸、中文 IME）按改动涉及的控件就近检查；未逐项穷举整个矩阵。
- **中文 IME 尚未端到端实测**：工单 04 的验收项包含它，因此该工单保持打开，直到这一步被真正验证，而不是按「其他项都过了」推断通过。
- **共享配置的「编辑器控件直接启动真实程序」这一段尚无自动化用例**：本轮尝试用原生测试覆盖它时，测试框架在窗口创建期间读取 `EditorApp` 会与进行中的更新冲突（`cannot read EditorApp while it is already being updated`），我没有为了让测试通过而改动产品代码。当前证据是：加载→合并→准备请求这条宿主侧路径有独立用例（含工具路径与项目文件解析），而「真实终端包启动真实程序」由工单 01–05 与 07 的真实包验收覆盖。这一段留作已知缺口，不声称已通过。
