# 插件 UI 解耦与文件显示布局总方案

日期：2026-10-05

稳定标识：`plugin-ui-decoupling`

状态：in-progress — 产品边界已确认，已拆为五个粗粒度工单 #62–#66。按用户要求在独立工作区的 `codex/plugin-ui-decoupling` 分支执行；没有纳入原工作区已有改动。

议题：[总方案 #61](https://github.com/T-miracle/Editor/issues/61)；[发布记录](../tickets/plugin-ui-decoupling/publication.json)保存真实编号与数据库 ID。

## Problem Statement

用户希望插件能够自行提供图标、功能按钮、内容面板及布局，安装、替换或移除插件时无需修改宿主。当前实现虽然已经将 Markdown 解析、SVG 内容绘制、终端逻辑和语言服务配置等放在插件中，但仍有部分插件界面依赖宿主的专属实现：编辑／分栏／预览模式及其按钮、同步滚动开关、顶部工具栏显隐偏好、部分图标和默认内容配色仍由宿主管理。插件能够提交内容，却不能完整决定这些内容怎样与原生编辑面板组合。

当前文件 Tab 与文本编辑会话绑定，中心区域围绕原生文本编辑面板和固定预览模式组织。这使图片等不需要文本编辑的文件也必须经过文本打开流程，无法自然表达“文件已打开，由图片插件显示，且没有文本编辑面板”的状态。把插件内容改成独立 Tab 也不符合用户要求：文件 Tab 栏只负责列出已打开文件，插件改变的是当前文件的显示布局。

底部左侧工具栏还需要明确区分两种用途。靠左的按钮负责窗口显隐；短竖线右侧的按钮负责插件功能。如果两者继续混用，或右侧功能按钮继续写在宿主中，新增插件仍然需要宿主配合修改，用户也难以判断按钮控制的是窗口还是当前内容。

用户同时需要可靠的状态与恢复行为：同一工作区的同类文件一起切换显示模式；多个插件支持同一文件类型时能够明确选择；插件失效时仍能继续编辑文本，或知道图片为什么无法显示。解耦不能以丢失未保存文本、光标、Undo／Redo 或把二进制文件强行当文本打开为代价。

## Solution

保留文件 Tab 栏，把中心区域改为通用的“当前文件内容容器”。当前选中的文件显示提供者负责提交内容与内部布局；宿主通过公开接口执行布局、绘制原生控件、分发输入并管理资源。原生文本编辑面板成为可以组合、也可以省略的宿主组件。

三个典型场景如下：

- 打开 Markdown：文件仍位于原来的 Tab 栏。Markdown 插件可以安排仅编辑、编辑与预览共存或仅预览，并提供自己的模式、同步滚动和顶部格式工具栏显隐按钮。宿主不规定所有插件必须采用这三种模式。
- 打开 PNG：文件仍位于同一 Tab 栏。兼容的图片显示插件可以只提交图片内容面板，无需创建文本编辑面板；没有可用提供者时保留该 Tab，并显示原因及重新选择／重试入口。
- 使用终端：终端窗口显隐按钮放在左侧窗口按钮组；新建终端、终端菜单等插件功能按钮放在右侧插件工具按钮组，业务由终端插件实现。

### 职责归属

| 事项 | 插件提供 | 宿主提供 |
| --- | --- | --- |
| 文件显示 | 适用文件类型、内容面板、内部布局与领域交互 | 文件身份、提供者选择、通用内容容器、布局执行与原生绘制 |
| 原生文本编辑 | 在布局中声明是否使用及放置位置；通过公开接口请求编辑 | 唯一文本会话、原生编辑组件、IME、选择、Undo／Redo 与保存 |
| 窗口按钮 | 插件窗口入口、图标、名称与窗口贡献 | 注册、绘制、显隐执行及实际窗口状态；系统文件树入口也可放在此组 |
| 插件工具按钮 | 按钮、图标、提示、适用条件、选中／禁用状态与功能处理 | 通用按钮行为、外观、事件路由及各组的溢出菜单 |
| 配色与图标 | 包内资源和默认领域内容配色 | 安全加载、主题覆盖与通用原生控件外观 |
| 显示偏好 | 布局模式、同步滚动、插件工具栏显隐的持久化与恢复 | 公开私有存储、工作区作用域及实际生效状态的校验 |
| 故障与权限 | 可恢复业务状态及有效的新内容 | 权限检查、过期结果拒绝、资源清理、通用恢复与错误界面 |

### 领域术语

| 术语 | 本方案含义 |
| --- | --- |
| 文件 Tab | 已打开文件的入口；不表示插件页或必然存在的文本编辑会话 |
| 文件上下文 | 当前文件身份、所在工作区及其可用能力；非文本文件也有文件上下文 |
| 文本编辑会话 | 文本文件的内容、选择、输入法与撤销状态，由宿主维护；不是所有文件都需要 |
| 文件显示提供者 | 声明支持某类文件、提供中心内容及布局的插件贡献 |
| 中心布局 | 当前提供者提交的文件内容组合；可包含原生编辑面板和插件节点，也可只包含插件节点 |
| 原生编辑面板 | 宿主提供、引用现有文本会话的可组合组件；不向插件交出可变文本或撤销栈 |
| 窗口按钮组 | 底部左侧靠左的一组按钮，专门控制窗口显隐 |
| 插件工具按钮组 | 短竖线右侧的一组按钮，控制适用于当前功能上下文的插件功能 |
| 功能上下文 | 当前文件或当前活动插件窗口；点击底栏按钮时仍指向原功能目标 |
| 显示偏好 | 同一工作区、同一文件类型的共享显示选择；插件偏好还须按插件命名空间隔离 |

## User Stories

1. As an 编辑器用户, I want 原有 Tab 栏只列出已打开文件, so that 查找文件时不会混入插件页面。
2. As an 编辑器用户, I want 切换文件 Tab 时切换中心文件内容, so that Tab 始终是对应文件的入口。
3. As an 编辑器用户, I want 插件安排当前文件的中心内容布局, so that 显示方式符合文件用途。
4. As an 编辑器用户, I want 插件内容与原生编辑面板共存, so that 能在同一布局中编辑和查看文件。
5. As an 编辑器用户, I want 插件能够隐藏原生编辑面板, so that 不需要编辑时可以只看插件内容。
6. As an 编辑器用户, I want 通过兼容查看器打开 PNG 而无需构造文本编辑器, so that 图片以图片形式显示。
7. As an 编辑器用户, I want 图片保留在普通文件 Tab 栏中, so that 各类文件采用一致的导航方式。
8. As an 编辑器用户, I want 同一文件只有当前选中的提供者控制整体布局, so that 多个插件不会互相覆盖界面。
9. As an 编辑器用户, I want 在兼容文件显示提供者之间选择, so that 文件的显示方式由我决定。
10. As an 编辑器用户, I want 按工作区和文件类型记住提供者选择, so that 不必为每个同类文件重新选择。
11. As an 编辑器用户, I want 安装其他提供者后保留当前选择, so that 安装顺序不会改变工作方式。
12. As an 编辑器用户, I want 切换布局提供者时其他插件继续启用, so that 不会连带失去无关功能。
13. As an 编辑器用户, I want 辅助插件与布局提供者一起贡献适用工具, so that 使用辅助功能无需让出整体布局权。
14. As an 编辑器用户, I want 同一工作区同类文件一起切换显示模式, so that 一个 Markdown 改为预览时其他 Markdown 也采用预览。
15. As an 编辑器用户, I want 不同工作区的显示偏好互相独立, so that 各工作区可以有自己的安排。
16. As an 编辑器用户, I want 共享显示偏好时保留每个文件自己的文本、光标和历史, so that 文档状态不会混在一起。
17. As an 编辑器用户, I want 重启后恢复插件显示偏好, so that 插件可用时继续采用原有布局和功能选择。
18. As an 编辑器用户, I want 已有显示偏好得到迁移, so that 本次改造不会重置我的选择。
19. As an 编辑器用户, I want 底部最左侧按钮只控制窗口显隐, so that 能区分窗口控制与功能控制。
20. As an 编辑器用户, I want 文件树入口也可保留在窗口按钮组, so that 系统窗口采用一致的分组方式。
21. As an 编辑器用户, I want 只改变中心布局的插件不自动增加窗口按钮, so that 窗口组只包含真实窗口入口。
22. As an 编辑器用户, I want 插件功能按钮位于短竖线右侧, so that 按钮用途一目了然。
23. As an 编辑器用户, I want 工具组跟随当前文件或活动插件窗口, so that 可用功能符合当前操作对象。
24. As an 编辑器用户, I want 点击工具按钮时保留原文件或窗口目标, so that 底栏获得焦点不会把操作发给其他对象。
25. As an 编辑器用户, I want 多个适用插件同时提供工具按钮, so that 选择一种布局不会隐藏有用的辅助功能。
26. As an 编辑器用户, I want 两组分别拥有自己的溢出菜单, so that 窄窗口中仍可区分窗口与功能控制。
27. As an 编辑器用户, I want 按钮准确显示选中和禁用状态, so that 能知道当前模式及可用操作。
28. As an 编辑器用户, I want 按钮名称和提示支持中英文, so that 能理解插件控件的用途。
29. As an 编辑器用户, I want 布局切换保留未保存文本、选择及 Undo／Redo, so that 改变视图不改变编辑会话。
30. As an 编辑器用户, I want 隐藏编辑器后停止向其输入但保留状态, so that 键盘与中文 IME 输入到达可见目标。
31. As an 编辑器用户, I want 文本显示提供者不可用时回到普通编辑界面, so that 能继续处理文件。
32. As an 编辑器用户, I want 宿主菜单能恢复具备文本能力的文件的普通编辑界面, so that 插件隐藏全部编辑控件时也有恢复入口。
33. As an 编辑器用户, I want 图片查看器不可用时保留文件 Tab 并说明原因, so that 能选择其他查看器或重试。
34. As an 编辑器用户, I want 恢复方式符合文件可用能力, so that 二进制图片不会被强行放进文本编辑器。
35. As an 编辑器用户, I want 切换或关闭文件后丢弃迟到插件结果, so that 旧内容不会显示在当前文件布局中。
36. As an 编辑器用户, I want 插件内容更新时输入仍然流畅, so that 预览工作不会阻塞原生编辑。
37. As an 编辑器用户, I want 保留 Markdown、SVG、终端和语言插件的已有功能, so that 解耦不会丢失正在使用的工具。
38. As an 编辑器用户, I want 插件布局支持深浅主题、键盘焦点、滚动和缩放, so that 操作与编辑器其他区域一致。
39. As an 插件作者, I want 在包内提供图标和内容配色, so that 插件不依赖宿主私有资源目录。
40. As an 插件作者, I want 声明工具按钮并处理业务事件, so that 新增功能无需修改宿主代码。
41. As an 插件作者, I want 使用公开布局与原生编辑组合能力, so that 布局不局限于固定的编辑／分栏／预览包装。
42. As an 插件作者, I want 访问独立于文本快照的受控文件资源, so that 查看器通过公开能力支持非文本文件。
43. As an 插件作者, I want 使用公开私有存储保存工作区显示偏好, so that 无需宿主增加专属偏好字段。
44. As an 插件作者, I want 使用与内置插件相同的公开接口, so that 第三方插件具有同等能力。
45. As an 插件作者, I want 明确的能力、权限和生命周期文档, so that 能正确处理失败、取消与资源清理。
46. As an 维护者, I want 无需修改宿主即可安装陌生身份的兼容插件, so that 可扩展性有真实行为证明。
47. As an 维护者, I want 更新或移除时撤销旧界面、事件与资源, so that 旧实例不能影响当前文件。
48. As an 维护者, I want 包版本、SDK 契约与消费者同步迁移, so that 不兼容包明确失败且用户数据得到保留。

## Implementation Decisions

### 1. 通用平台与插件业务的边界

- 扩展现有插件协议、运行时与宿主集成模块，提供文件显示、中心布局、原生编辑组件引用及两组按钮贡献所需的通用能力。复用现有包管理、节点树、画布、图片、事件、私有存储和资源生命周期机制，不为具体插件新建专用宿主入口。
- 插件提供业务声明与处理：图标、提示、按钮适用条件、选中／禁用状态、点击行为、布局模式及功能偏好。宿主负责执行经校验的声明；涉及窗口、文档与权限的权威状态仍以宿主为准。
- 宿主不得按插件 ID、语言名或服务器名决定按钮、布局、配色、提供者优先级或业务操作。已有公开能力范围内的插件新增、替换、禁用与移除不要求修改宿主。
- 声明式插件包仍可不带 WASM。静态资源和贡献不需要空钩子；动态状态、布局与业务交互通过可选 WASM 钩子实现。
- UI 保持原生 GPUI；插件提交受控声明和领域绘制内容，不加载原生插件模块，不直接持有 GPUI 对象。可见控件继续以 gpui-base 的行为为基座，由宿主本地 UI 层提供外观。

### 2. 文件 Tab 与可选文本会话

- 文件 Tab 管理打开文件、选择、关闭与文件身份；文本编辑会话只在文件具有文本编辑能力且需要该能力时建立。不得为了创建 Tab 强制解码二进制内容或构造文本编辑面板。
- 中心内容、底栏工具上下文与相关请求必须绑定同一活动文件身份。关闭后重开同一路径属于新目标，旧身份不能复用。
- 对文本文件，现有 DocumentSession／EditorState 继续维护唯一可变文本、IME、选择、布局与会话 Undo／Redo。插件只能通过公开文档接口读取或请求修改，不复制第二份可变文本状态或撤销栈。
- 布局替换、仅预览和手动恢复必须引用原文本会话，保留未保存修改、选择和历史。普通文件打开、保存、关闭及未保存提示的现有规则继续有效。
- 非文本文件具有独立的文件上下文与受控资源访问，不伪造文本 revision。其源内容与异步结果也需要可校验的身份和版本／有效期边界；具体公开类型在契约设计中定稿。

### 3. 插件可组合的中心布局

- 通用中心容器展示当前文件；被选中的提供者决定内部布局，宿主执行尺寸、滚动、输入与原生绘制。
- 原生编辑面板作为可引用的布局组件，与插件节点、画布、图片和工具栏组合；可仅显示编辑面板、与插件内容并排或上下组合，也可完全省略编辑面板。布局能力仍受通用节点校验和资源预算约束。
- 对文本文件省略编辑面板只改变展示，不丢弃原文本会话。对没有文本编辑能力的文件，布局不需要创建该组件或其文本会话。
- 当前固定的编辑／分栏／预览逻辑迁入相应插件。Markdown 与 SVG 可继续提供其已有模式，但这些模式不成为所有插件必备的宿主枚举或专属槽位。
- 所选提供者拥有当前文件的整体布局权；其他插件只能在已授权的公共贡献范围内参与功能，不得通过提交迟到或不匹配的布局接管中心。
- 隐藏编辑组件时正确移交焦点，避免不可见输入目标和残留 IME；重新显示时复用原编辑实体。按稳定节点身份更新界面，避免无关更新重建编辑器、跳动光标或闪烁。

### 4. 提供者选择与生效范围

- 插件声明所支持的文件类型和显示能力，宿主通过通用匹配得到兼容候选。多个候选时由用户明确选择，提供通用切换入口，不以安装顺序或插件 ID 排序静默覆盖选择。
- 选择按“工作区＋文件类型”记忆；同一范围的文件使用当前选择。选择其他提供者不等于禁用原提供者或其他插件。
- 新安装候选不覆盖已有有效选择。提供者暂时不可用时保留用户的选择记录并说明原因；回退界面不冒充一次新的用户选择。
- 可用性同时考虑能力版本、启用状态、工作区信任、权限及实例状态。受限、拒绝授权、停用和崩溃等已知原因应准确呈现，不统一误报为“未安装”。
- 提供者切换撤销旧布局及事件目标，再应用有效的新布局；失败进入与文件能力匹配的恢复路径。异步回复绑定发起时的目标、所选提供者及实例，不受后续切换影响。

### 5. 两组底栏按钮

- **窗口按钮组**位于底部左侧靠左位置，只提供窗口显隐入口。插件有独立窗口贡献时可声明对应按钮；宿主通过通用窗口接口执行显隐，以实际状态显示选中状态。系统文件树等窗口入口允许留在此组。
- 仅改变中心布局的插件不自动产生窗口按钮；不能把文件显示模式或顶部格式工具栏开关作为其默认窗口入口。
- **插件工具按钮组**位于窗口按钮组右侧，以短竖线分隔。模式切换、同步滚动、顶部格式工具栏显隐、新建终端和终端菜单等功能由相应插件贡献并处理。
- 插件有窗口和功能两类贡献时可同时进入两组。左组遵循窗口贡献的注册和显隐状态；右组依当前文件或活动插件窗口筛选，允许多个适用插件共同提供工具。
- 点击底栏控件前保留功能上下文；控件获得焦点不应把操作目标改为底栏自身。事件携带发起目标、有效状态版本和实例归属，目标已失效时拒绝操作。
- 原生按钮的焦点、键盘、指针、提示及禁用交互由通用 UI 层实现；插件提供功能含义和本地化资源。宿主不能从按钮位置或图标猜测业务含义。
- 两组分别拥有自己的“更多”溢出菜单，底栏保持单行，短竖线保留分组关系。溢出项保持相同状态、上下文和事件语义，不合并成一个混用菜单。

### 6. 显示偏好、权威状态与迁移

- 插件通过公开私有存储保存与恢复其布局模式、同步滚动、顶部工具栏显隐等偏好。插件命名空间内按“工作区＋文件类型”组织；不同工作区独立。
- **同一工作区同类文件一起切换显示模式**。例如 A.md 改为仅预览后，切换到 B.md 也采用仅预览，恢复 A.md 不会回到另一个模式；这不是每个文件独立记忆模式。
- 共享的是显示选择，文档内容、选择、光标、滚动位置与撤销历史仍属于各自文本会话。同步滚动表示同一文件布局内的相关内容协调，不把不同文件的文本或滚动状态合并。
- 宿主负责提供者选择及实际布局、窗口、文档和授权状态；插件保存的偏好是待应用意图，不能替代宿主对有效目标和执行结果的校验。
- 多个文档／实例使用同一偏好范围时，须通过公开存储及必要事件保持一致；不在宿主新增 Markdown、SVG 或终端专属偏好字段。
- 对已有宿主保存的预览模式、同步滚动和工具栏显隐设置进行有限、可测试的版本迁移，导入插件私有数据，保留其他设置与数据。迁移规则遇到历史范围差异时先依据实际旧数据定稿，不凭空选择一个文件的状态覆盖全部文件，也不直接清空。

### 7. 图标、内容配色与资源

- 插件贡献使用包内图标或公开节点图标资源，覆盖窗口、工具按钮、文件类型及面板标题。移除对宿主私有图标名称和插件专属内嵌资源的依赖；缺失资源明确校验失败，不借宿主目录暗中补齐。
- Markdown 的 GitHub／Primer 内容配色、终端 ANSI 默认调色板等领域默认值由插件提供。用户主题可通过通用主题契约覆盖；按钮、菜单等原生组件外观仍由宿主本地 UI 层统一实现。
- 深浅主题、字体和缩放变化经公开上下文通知插件并更新可见内容，包内资源必须满足当前协议的格式、大小、路径及归属校验。
- 通用文件资源接口为非文本显示提供受控数据访问；读取必须校验文件上下文、规范化路径、符号链接边界、权限与实例归属。当前依赖文本来源版本的图片接口不能直接假定为完整二进制文件显示契约。

### 8. 恢复、失效与更新

- 当前文本文件的所选提供者无法使用、崩溃、停用或失去必要能力时，中心区域回退到原生普通编辑界面，复用原文本状态；不能因恢复丢失未保存修改或 Undo／Redo。
- 宿主菜单提供通用 **“恢复普通编辑界面”** 操作。仅当当前文件具备文本编辑能力时提供该操作；插件隐藏编辑面板甚至没有恢复按钮时，用户仍可从宿主菜单恢复。
- PNG 等没有文本编辑能力的文件不做文本回退。保留文件 Tab，显示无可用查看器或准确错误原因，提供重新选择兼容提供者或重试入口；不强行解码二进制内容。
- 恢复条件依文件能力判定，不在宿主写某个扩展名或插件 ID 的专属业务分支。自动故障回退不静默改写用户的提供者选择或插件显示偏好。
- 隐藏、关闭、切换、停用、卸载和更新分别依原有生命周期撤销相应界面、事件目标、订阅、文件资源与异步请求。旧文件身份、旧 revision、旧提供者选择及旧实例的结果不能重新激活已撤销界面。
- 继续遵守更新的准备、激活和回滚事务；失败保留或恢复旧实例与受管私有数据，成功后撤销旧资源。快照恢复逻辑状态，不承诺恢复进程内存或回滚外部副作用。

### 9. 响应性与编辑接缝

- 原生文本输入先更新唯一文本状态；插件解析、渲染和布局更新不得阻塞输入，也不得建立第二份可变文档作为性能捷径。
- 沿用后台插件执行、增量 UI 与版本检查接缝，避免每个字符触发无关的全树重建。当前 Markdown 输入卡顿仍需以实际回归证明改善，不能因架构迁移自动标记已解决。
- 布局切换保留可复用的原生组件及事件目标；可见编辑区高度、主题、滚动、光标和中文 IME 必须通过真实交互验证。

### 10. 契约与迁移对象

以下是本规格要求的公开语义，不是已存在的接口名、字段或已分配的能力版本：

| 契约面 | 必须表达的内容 | 关键约束 |
| --- | --- | --- |
| 文件显示贡献与选择 | 支持类型、提供者身份、可用性、用户选择范围 | 内置与第三方一致；新增候选不静默覆盖 |
| 文件上下文与资源 | 非文本也可表达的目标身份、权限、内容有效期与资源访问 | 不强依赖文本快照；不能跨工作区或实例借用资源 |
| 中心布局与原生编辑引用 | 插件布局及可选的已有编辑会话引用 | 仅所选提供者安排整体布局；不复制文本与撤销状态 |
| 窗口与工具贡献 | 分组、归属目标、图标、本地化、状态及事件 | 窗口显隐与插件业务职责分明；过期事件拒绝 |
| 私有显示偏好 | 插件隔离的工作区／文件类型作用域与恢复 | 同类文件一起切换；宿主实际状态仍为权威 |
| 失效与恢复 | 不可用原因、撤销、重试及可用后备能力 | 文本与非文本恢复不同；不改变文件 Tab 的用途 |

- 实施对象包括宿主通用 UI 集成、文件与文本会话衔接、协议与 SDK、运行时资源验证，以及 Markdown、SVG、终端、示例和已有语言插件的受影响资源与消费者。此清单用于迁移盘点，不是运行白名单。
- 将现有宿主专属模式、工具按钮、图标和领域配色移入对应插件；保留原有功能。顶部 Markdown 格式工具栏已有的插件节点实现可继续复用，重点迁移其宿主开关和关联偏好。
- 在正式实现前定稿公开契约、能力协商、权限、错误、取消和生命周期，并更新 SDK 文档、示例和消费者。包版本、协议版本和能力版本分别处理；修改交付插件包须同步提升清单版本并核对产物。
- 独立插件仍通过宿主的公开 SDK 构建入口使用内嵌缓存，不依赖仓库内部 crate 路径或附带 SDK 源码副本。不新增旧协议运行兼容分支；不兼容包明确提示更新，用户设置与私有数据通过有限迁移保留。

## Testing Decisions

### 主要测试接缝

沿用用户仓库约定和插件平台总方案中已经确认的一个主要入口：**真实或最小有效插件包 → 公开 Package／Manager → 宿主文件与原生 UI 集成 → 用户可观察结果**。

包安装、声明匹配、选择、按钮事件、布局应用、文档操作及失效清理沿同一产品流程验证。运行时与 GPUI 测试是这个入口的不同层次；不为 Markdown、终端、PNG 查看器或某个测试插件新增专用宿主 API。必要的新文件显示与布局接缝也是产品公开能力，供真实插件使用，不是测试后门。

测试断言打开的文件、显示的布局、按钮状态与实际操作结果、文本和撤销是否保留、权限是否拒绝、旧资源是否失效。不断言私有映射结构、辅助函数调用次数或固定内部枚举，不能只通过检索“不含插件 ID”证明可扩展。

### 验收矩阵

| 编号 | 行为 | 可观察证据 |
| --- | --- | --- |
| U01 | 文件 Tab 与中心内容 | 文本、SVG 和 PNG 均进入文件 Tab；没有独立插件 Tab；切换后中心目标正确 |
| U02 | 非文本打开 | PNG 由公开文件显示夹具展示，不进入文本解码／编辑流程；显示并关闭不触发文本保存操作 |
| U03 | 可组合布局 | 陌生插件通过公开布局组合原生编辑器、工具栏与画布；并排、上下及仅插件内容均可操作 |
| U04 | 原编辑会话保留 | 未保存文本、选择与 Undo／Redo 跨布局切换、提供者切换和手动恢复保持正确 |
| U05 | 多提供者选择 | 同类型两个不同 ID 的兼容提供者可切换；重新打开按工作区／类型恢复；新安装不覆盖 |
| U06 | 布局权与辅助工具 | 未选提供者不能替换中心布局；其他适用插件的工具仍可出现并执行 |
| U07 | 同类文件共享偏好 | A.md 修改模式后 B.md 一起采用；不同工作区独立；两个文件内容与历史互不影响 |
| U08 | 偏好迁移与重启 | 旧模式、同步和工具栏设置保留；重启恢复；损坏或不适用数据不覆盖其他用户数据 |
| U09 | 窗口按钮组 | 插件窗口与系统文件树显隐正确；仅中心布局插件不自动出现窗口按钮 |
| U10 | 插件工具按钮组 | 模式、同步、格式工具栏及终端功能由插件控制；多个贡献状态与实际结果一致 |
| U11 | 上下文与溢出 | 活动文件／窗口切换后工具更新；点击不改变原操作目标；窄窗两组各自溢出且仍可操作 |
| U12 | 图标与主题 | 包内图标正确显示；缺失及跨包路径被拒绝；深浅主题、内容配色及用户覆盖生效 |
| U13 | 文本故障恢复 | 停用、崩溃、权限失效及手动菜单恢复后可继续编辑原文本；隐藏输入不截获按键 |
| U14 | 非文本故障恢复 | 无查看器、崩溃或停用后保留 PNG Tab、原因及选择／重试入口；无强制文本回退 |
| U15 | 迟到结果 | 文件切换、关闭重开、revision 变化、提供者更换及实例更新后旧布局／事件不串台 |
| U16 | 生命周期与事务 | 停用／卸载撤销按钮和资源；更新准备／激活失败保留或恢复旧实例及偏好；成功撤销旧资源 |
| U17 | 权限与信任 | 受限工作区不启动插件；越界文件、跨实例资源、错误能力版本和未授权访问明确拒绝 |
| U18 | 原生交互 | 真实键盘、中文 IME、焦点交接、滚轮、缩放、编辑区高度、主题及中英文提示正确 |
| U19 | 响应性 | 连续输入期间文本及时显示、光标稳定；插件更新不阻塞；过期内容不覆盖新 revision |
| U20 | 既有能力与独立构建 | Markdown／SVG／终端／示例／语言能力回归；不同身份的独立插件构建安装无需修改宿主 |

U02 的验证要能区分文件打开与文本打开两种公开路径；不以“内部 EditorState 数量为零”的私有结构断言代替行为证明。必要的资源契约校验测试可补充验证，但不能替代真实文件和 UI 流程。

### 可复用的先例与夹具

- 公开包与组合 UI：既有组合 UI、图标、图片和增量节点的运行时验收。
- 原生文档与布局：既有 Markdown 编辑区高度、首次打开、图标工具栏、同步滚动、输入响应和过期视口回归。
- 故障与生命周期：现有恢复、面板清理及热更新事务验收。
- 现有 Markdown、SVG 和终端作为迁移回归对象；另用不同身份的最小文件显示／布局提供者证明接口通用。PNG 夹具覆盖非文本显示，不自动扩大为新的完整图片编辑产品。

真实 WASM 用例先按 ignore 原因和验证文档构建包／夹具，再显式运行相关 ignored 测试；跳过不计为通过。测试使用隔离工作区、插件安装与私有数据目录，不操作用户实际安装数据。

### 检查与交付口径

实现阶段先做受影响模块的针对性测试，再执行仓库要求的格式检查、非 UI workspace 测试和 workspace 编译检查。应用层追加相关 GPUI 测试及原生交互；SDK 变更追加宿主构建和独立 SDK 分发验证。编译通过不能替代 U01–U20 的行为证据。

本次只整理并发布规格，检查文档结构、链接、路径、已确认约定和 diff；不要求无关 Rust 构建，不宣称新功能或既有性能缺陷已通过验收。后续验收记录逐项标明命令、结果、跳过项和平台限制。

## Out of Scope

- 将独立插件页面混入文件 Tab 栏，或为中心布局插件自动创建窗口按钮。
- 图片修改、编码、导出及完整图片编辑插件交付；本方案确认非文本文件显示能力与 PNG 验证场景。
- 多窗口、多根工作区、自由停靠和插件任意修改整个宿主窗口布局。
- 多个插件同时争夺中心整体布局，按安装顺序或插件 ID 自动覆盖用户选择。
- WebView／前端框架 UI、原生动态插件模块、复制 GPUI 源码或第二份可变文本与撤销栈。
- 新的在线市场、权限模型重写、全局工具链安装和旧协议运行兼容层。
- 将运行／调试／构建总方案一并实现，或因本规格回写历史工单完成状态。
- 本次直接编码、拆分发布实施工单、提交／推送代码、指派执行人或关闭历史议题。

## Further Notes

### 对旧约定与当前实现的替代范围

| 基线或现状 | 本规格处理 |
| --- | --- |
| 文件打开入口必须创建文本会话 | 扩展为文件 Tab 独立于可选文本会话；非文本文件可由显示提供者直接呈现 |
| 宿主固定编辑／分栏／预览模式及开关 | 布局与功能迁入插件；宿主提供通用可组合组件和执行接口 |
| 宿主保存插件显示偏好 | 迁入公开插件私有存储；提供者选择及实际窗口／布局状态仍由宿主管理 |
| 每个文件独立保留显示模式的可能方案 | 按最终确认采用同工作区同类型一起切换；不改变每个文档独立的内容与历史 |
| 插件内容可作为独立文件 Tab 的建议 | 用户已明确拒绝；本方案不采用 |
| 所有故障统一回到文本编辑 | 按文件能力分别恢复；无文本能力的文件保留 Tab 并提示查看器问题 |
| 插件依赖宿主私有图标和领域默认配色 | 资源与默认值移入插件；保留通用主题覆盖及本地原生控件外观 |
| 原需求的文本中心边界 | 本次确认扩展到 PNG 等非文本文件显示；不扩大为非 UTF-8 文本的无损编辑与编码转换 |
| 唯一文档状态、revision 校验、信任与权限、动态 grammar、原生 UI 基座、更新事务 | 继续有效，未被本规格替代 |

本规格在上述 UI、文件显示和偏好范围补充并替代旧行为；插件平台其他规则继续遵守。历史需求、开发计划和已完成验收保持其当时记录，不追溯修改为本功能已经完成。

### 尚需在公开契约设计中定稿的细节

能力名称与版本、清单字段、文件内容有效期模型、原生编辑引用方式、提供者与工具上下文事件形状、错误枚举、按钮排序及溢出细节、偏好存储键和旧数据冲突迁移规则需要在实施设计中落实。这些是技术细化，不是新增产品选择，也不能用实现方便改变上述已确认边界。

“文件类型”的精确匹配与规范化规则应与既有贡献系统一致，并在契约中说明；不能把示例扩展名变成宿主硬编码白名单。“恢复普通编辑界面”的菜单位置尚未指定，实施时沿用现有通用菜单组织。
