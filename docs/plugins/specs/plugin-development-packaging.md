# 插件打包与隔离开发运行

2026-10-08 用户通过逐项评审确认，并授权在新工作区、新分支实施。用户最新要求优先于历史脚本入口与“所有配置来自插件”的旧约定。

## 已确认范围

- GUI 与 CLI 共享插件项目根部 `nanobug-plugin.json`；明确收集资源，完整构建可选 WASM 和已声明原生产物。
- 默认 ZIP 在各插件项目根部；本地配置支持输入与系统目录选择，CLI 支持输出覆盖。共享输出相对项目，本地 GUI 相对宿主工作区，CLI 相对命令目录。
- 多项目各自产出 `<id>-<version>.zip`，逐项报告；任一失败整体失败。成功原子覆盖同名包，失败保留旧包，不自动改包版本。
- 宿主内建“插件打包”“插件调试”模板，在配置树正常新增草稿，不自动创建配置；插件全部禁用时也保留。
- 插件调试指开发运行、日志及效果观察，不实现 WASM 源码断点。Run 启动独立实例，Build 只准备产物，Debug 禁用并给出原因。
- 测试工作区可选，默认插件项目。首次配置确认信任／权限；新增权限停止后重新授权。
- 开发实例加载随附插件与开发插件，同 ID 使用开发版；配置、安装记录、私有数据与历史均隔离。按配置保留开发数据，可重置并保留旧目录备份。
- 默认手动重载，可选监视文件增量构建；验证和激活失败保留旧版及受管数据，错误出现在输出。
- Windows 实测；macOS/Linux 使用兼容接口，不声称跨端验收。
- 不调用原 `scripts/` 或迁至 Codex 工作区的脚本；不静默安装缺失工具链。

## 实现边界

`plugin-runtime::development::Project` 封装项目读取、构建、资源收集、包准入和原子 ZIP。目录候选与 ZIP 使用相同 `Package` 校验；宿主 GUI、CLI 均调用此公开通用模块，无插件 ID／语言特判。

Rust 访客由 Cargo compiler-artifact 消息定位 `cdylib` 产物，使用宿主内嵌 SDK 缓存及 `wasm32-wasip2`；原生工具按可执行程序和 argv 调用，明确平台。编译缓存使用用户缓存目录下的短路径，避免 Windows MSVC 路径长度问题。

开发控制器持有独立 GPUI 进程树，用不可变目录和会话标识交付重载。现有管理器 actor 执行后台准备和事务切换，不另设可变文档或私有数据所有者。宿主运行记录复用已有运行控制，输出有界；信任撤销、停止、强制停止和窗口退出撤销本任务进程。

宿主模板身份使用不能成为插件 ID 的保留标识。两种模板不是公开 guest provider 版本变更，不提升协议／能力版本，也不修改现有插件业务行为。新增的项目描述不属于安装包资源。

项目格式与读者说明唯一正文在 `website/` 双语页面；命令放在根双语 README。14 个现有插件项目提供示例描述。旧辅助脚本删除继承用户已授权的清理，不执行脚本归档副本。

## 验收与交付

针对性测试覆盖默认输出、显式输出、原子覆盖、失败保留、资源目录内输出、取消、路径边界、目录／ZIP 等价，以及无插件的真实 GPUI 模板创建与保存。实际 WASM、原生构建、开发重载和 Windows UI 结果见[验收记录](../verification/plugin-development-packaging.md)。完成状态只以该记录的实际结果为准。

工作基线为已提交的主分支 `ebe40c2`；原主工作区中的未提交 UI、安装器及其他改动不计入本任务。新工作区只继承项目规则、必读基线文档与脚本删除。
