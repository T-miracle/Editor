# 打包与开发运行

[English](../../en/sdk/packaging.md)

插件项目在源码旁维护 `nanobug-plugin.json`。这份版本化描述由编辑器的“插件打包”“插件调试”配置和命令行入口共享，与安装后的 `manifest.json` 分离，可以纳入 Git。本地配置覆盖项目和输出选择，不改写共享描述。CLI 使用方式见仓库 README。

请选择包含该文件的工作区副本。文件缺失时，编辑器会指出缺失的项目描述，并提示选择已配置的插件项目或补充构建描述；不会根据 `manifest.json` 推断打包规则，也不会静默改用另一个工作区。

## 描述格式 1

```json
{
  "version": 1,
  "manifest": "manifest.json",
  "output": ".",
  "wasm": { "manifest": "Cargo.toml" },
  "assets": [
    { "source": "README.md", "destination": "README.md" },
    { "source": "queries", "destination": "queries" }
  ]
}
```

`version` 必须是 `1`。`manifest` 默认 `manifest.json`；`output` 默认 `.`，即插件项目根目录。共享输出路径必须相对项目。本地 GUI 目录选择或 CLI 覆盖优先，可选择源码项目之外的目录。包、协议、能力和描述格式的版本彼此独立，打包不会自动修改清单版本。

纯资源包省略 `wasm`。Rust 访客使用宿主管理的内嵌 SDK 和 `wasm32-wasip2`，Cargo 清单相对插件项目。Cargo 必须报告恰好一个匹配的 `cdylib` WASM 产物，可选 `wasm.library` 指定目标名。产物复制到安装清单的 `component` 路径，无需 SDK 源码副本或指向宿主仓库的依赖。缺失构建工具或目标会报错，不会自动安装。

`assets` 明确列出递归复制的文件或目录。来源相对项目，目标相对包。安装清单自动生成，不得重复加入 assets。必须包括全部引用的声明、grammar、查询、图标、许可及其他资源；未列入的源码不会收集。符号链接、越界路径、重复目标和缺失引用均拒绝准入。ZIP 根部直接放置包文件。文件数与展开大小上限和安装准入一致，开发目录使用同一套校验。

## 原生产物

可选 `native` 项在项目目录调用可执行程序及字面参数数组，必须声明 `windows-x86_64` 等准确平台，与所选平台及当前宿主平台一致。拒绝未声明的原生交叉编译。这些项描述构建工具；运行时服务的安装与权限仍由安装清单声明。

```json
{
  "version": 1,
  "native": [
    {
      "program": "rustc",
      "args": ["native/bridge.rs", "-o", "{build}/bridge.exe"],
      "platform": "windows-x86_64"
    }
  ],
  "assets": [
    { "source": "{build}/bridge.exe", "destination": "native/bridge.exe" }
  ]
}
```

参数支持 `{project}`、`{build}`、`{profile}`（`debug` 或 `release`）。`{build}` 是私有编译缓存，不是分发目录；资源来源可使用 `{build}/` 收集生成的原生文件。分发清单的服务产物哈希按收集后的字节计算，不修改源清单。原生工具直接启动，拒绝 Shell、脚本解释器与归档的打包辅助脚本。项目构建工具及 Cargo build script 使用开发者的 OS 权限。

## 生成 ZIP

打包构建全部声明组件，收集资源，校验完整候选，生成 `<id>-<version>.zip`。校验后的 ZIP 在同一输出目录原子替换旧包，构建失败保留旧包。输出选在资源目录时，不会把旧 ZIP 嵌入替代包。多个项目各自产生 ZIP，未覆盖时使用各自默认位置；批量逐项目报告结果，任一失败或输出碰撞时整体返回失败。

## 不生成 ZIP 的开发运行

开发运行构建并校验不可变目录候选，再启动独立编辑器进程。首次运行初始化随附插件，同 ID 使用开发版本。设置、插件安装、私有数据、历史及运行配置使用独立数据目录。同一配置保留数据；“重置开发环境”创建新环境，并将旧目录保留为备份。重置前需停止实例。

测试工作区默认使用插件源码目录，也可单独选择。GUI 启动确认工作区信任和插件权限；CLI 启动要求显式权限授权。新增权限需停止后重新授权运行；更改开发插件 ID 同样需要重新启动配置，以重新建立随附插件的替换关系。这些授权不改变主编辑器的信任和安装记录。

手动“重新加载插件”构建、校验并事务激活候选，同时保留私有数据。可选自动重载监视声明的源码／资源，合并短时间变化并使用编译缓存。准备或激活失败保留原先可用版本，在输出中报告错误。旧控制器的请求不能切换重新启动的实例。停止回收开发进程树，强制停止立即终止。

“运行”启动隔离编辑器；“构建”仅准备产物，不生成 ZIP 或开发窗口。插件调试模板提供日志和效果观察，暂不支持 WASM 源码断点，“调试”按钮禁用并说明原因。已安装插件全部禁用时，宿主模板仍然可用。详见[用户指南](../guide/run-debug-build.md)。

Windows 提供原生验收覆盖。macOS/Linux 使用兼容的文件和进程接口，但尚未在这些系统验证；原生构建声明必须符合实际系统和架构。
